# Chroma owned vector control

`catalogue-chroma-owned-vector` is a default-off, fixed functional control for the installed Chroma 0.5.23 v2 API. The server supplies only this closed profile ID at launch. Its runtime binds the `document-store/chroma` Deployment, Service, container, port 8000, exact image digest, and three installed source-file SHA-256 values recorded in round 12. A single ready Deployment→ReplicaSet→Pod and Service→EndpointSlice route must agree before and after each request. The source files are hashed inside the exact Pod before and after each request.

The control generates one 96-bit nonce and records its collection name, document ID and SHA-256 in the private job journal before mutation. It requires the installed typed `400 InvalidCollection` response naming that exact collection before one `get_or_create=false` create. It persists any returned UUID before validating the rest of the create acknowledgement, then reads back that UUID and nonce marker. It adds one synthetic document with the explicit `[0.1, 0.2, 0.3]` embedding, verifies exact-ID get and one self-query, and checks the document hash, marker, embedding and distance. It does not list or adopt existing collections, call an embedding model, or download a provider package.

Each application request uses one bounded exact-Pod exec to `127.0.0.1:8000`. The Kubernetes bearer authenticates only the exec control connection and is never placed in the local Chroma HTTP request. Requests have an absolute deadline, an 8192-byte response bound, no redirects and no retry. An intent is durable before every mutation. An ambiguous create, add or delete result is never replayed or treated as absence.

Cleanup rereads only the fresh name and requires its returned UUID and nonce marker to match the create receipt before one name-based DELETE. It then requires the typed exact-name absence response. Chroma 0.5.23 does not offer an atomic UUID-conditional delete at this route: another actor replacing the same unguessable name between preflight and DELETE would be a residual race. The control withholds deletion when replacement is visible at preflight; it does not claim server-enforced conditional cleanup. Any uncertain mutation or cleanup remains `inconclusive` and `UnsafeToRetry` for exact-ID review. A functional pass requires the exact vector oracles and confirmed cleanup.

This direct control has no SecurityEvent dispatch. `securityOutcome`, installed defense, brain and actuator evidence are `NOT_EVALUATED`. It does not test tenant authorization, a model-repository advisory, Phorvex detection, failover or PVC durability.
