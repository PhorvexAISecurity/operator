# Installed MCP session functional baseline

`catalogue-mcp-session-baseline` is a fixed, benign catalogue profile. It is visible but unavailable by default. Its only application traffic is the six fixed requests to one freshly pinned `mcp/mcp-server` Pod's `/mcp` route: initialize, initialized notification, exact two-tool list, one `store_directory(hours)` static read, DELETE of the in-memory session, and a same-session `tools/list` refusal. A functional pass requires the 76-byte static result hash and the exact 404 / JSON-RPC `-32600` invalidation result. It does not test caller authorization, business writes, providers, Phorvex detection or response.

The worker reads the current Deployment→ReplicaSet→Ready Pod, Service and EndpointSlice identities and the mounted `mcp-code/server.py` ConfigMap; it also hashes the actual `/app/server.py` and three installed SDK files and checks FastMCP 3.4.7/MCP SDK 1.29.0 inside the exact container. This pins current files and package versions, **not bytes already loaded into the Python process**. Source and target are checked before application requests and again at completion. Session IDs and tool text remain in worker memory; journals and API results contain only typed statuses, identities and hashes. A worker crash or ambiguous initialize/DELETE leaves an explicit unsafe-to-retry cleanup debt because the session ID cannot be recovered from the journal.

## DevOps opt-in

Set `phorvex.console.catalogueV1.enabled=true` and `phorvex.console.catalogueV1.mcpSession.enabled=true` only after the current installed image/source matches the reviewed contract. Chart defaults are `namespace=mcp`, `deployment=mcp-server`, `service=mcp-server`, `container=mcp-server`, `port=8000`, `sourceConfigMap=mcp-code`, `sourceKey=server.py`; supply both nonempty `imageID` and `sourceSHA256`. This implementation admits only imageID `docker.io/library/python@sha256:90744cff8f32887f075c47d747a173ff333e9e98801667af93c357fa9f5e28ff` and source SHA-256 `483009cd01640e9f604a21f16aa890539566f53a25fd7dc478bc43c1831212c5`. A source or image change needs a new review/code pin rather than just a tag or arbitrary value. The chart adds one `mcp` Role and RoleBinding only when the profile is enabled: exact service/ConfigMap reads, Deployment/ReplicaSet/Pod/EndpointSlice reads, fixed source-check `pods/exec` create, and fixed protocol `pods/proxy` create/delete. No Secret, namespace, policy, workload or database write grant is added.

The console subject grants must authorize the fixed logical target `default` **and** tenant `mcp`; simply setting chart values does not grant a user access. The public catalogue readiness row means configuration is present. Each launch still verifies current installed authority and protocol, and the result remains an unscored benign functional control. The historical direct round-10 receipt is protocol evidence, not a console-run result. No shared deployment is implied by this source change.
