# Phoenix AMTD — Decision Log (Resolving All 36 Forks)

This log records the resolution of all 36 decision forks surfaced in `gap-spec.md` into a single locked Phoenix architecture. It optimizes for the most **complete and accurate** Phoenix that stays **faithful to the 4 papers + 2 product pages** while never asserting a capability the code cannot deliver.

## How to read this document

Every decision carries a **Paper basis** label. The accuracy discipline is the whole point of this exercise, so the labels are load-bearing:

- **[PAPER-SPECIFIED]** — the corpus pins the answer (or its shape). We implement the paper, not a preference.
- **[UNDERSPECIFIED → design decision]** — the papers name the *what* but are silent on the *how*. The chosen answer is **OUR design choice**, flagged as such, never dressed up as "reproducing Phoenix."
- **[R6-PAPER-ONLY]** — an asserted/marketing/dashboard figure with **no measurement code** anywhere in the 5 repos. Held as a *target-to-confirm*, never adopted as fact or as a CI gate.
- **[PAPER-CONTRADICTION → design decision]** — the corpus conflicts with itself for the same concept. We pick one reading, document it, and never silently drop the loser.

### The global DESIGN RULE (stated once, up front)

1. **Rule #1 — every workload effect is a Strategy entry and SecurityEvent-triggerable.** Every effect Phoenix performs on a workload (`Delete`/`Quarantine`/`Debugger`/`CustomAction`/`Rotate`/`WarmSwap`/`Regenerate`/`NodeRotate`) is a `MaxProperties=1` `AMTDAction` expressible as one `Strategy[]` `{Rule → AMTDAction}` entry **and** reachable by emitting a `SecurityEvent` the matcher routes. Nothing is reachable only via an internal timer or a hard-coded path. The hard-coded NIM `FindTimedEvent` gate dissolves into a `{Type:'timed',Source:'TimeBasedTrigger'}` strategy rule.
2. **Rule #2 — a computed score can select an action while exact rules stay byte-compatible.** The matcher is relaxed so an anomaly score/threshold can select an action, **while existing exact-match `{Type,ThreatLevel,Source}` rules behave byte-for-byte as today.**

Two structural distinctions keep Rule #1 honest:
- **Class-(A) actions** are the rule-#1 surface (the eight effects above).
- **Class-(B) reconciles** are owned-CRD desired-state loops (a `WarmInferenceSet` keeping N shadows Ready; a `NodeRotation` finishing an in-flight drain across operator restart). They realize/continue what the matcher already chose or hold inventory; they **never initiate** a rotation/swap/node-move the matcher did not first select. They are not trigger paths.

## Locked kernel (read this first)

Everything in the themed sections plugs into this spine. The kernel decisions (`D1`, `D2`, `D3`, `D21`, `D19`, `D26g`, `D7g`) are not re-litigated anywhere below.

### Config home — `D1` HYBRID

Cadence/mutation/score tuning is **EMBEDDED** on `AdaptiveMovingTargetDefenseSpec` as optional pointer blocks (`nil` ⇒ today's behavior), reusing `PodSelector`, `Strategy[]`, the `AMTD_MANAGED_BY` enrollment, and existing RBAC:

- `InferenceRotation *InferenceRotationSpec` — holds `RotationPolicy` (cap#4 cadence/jitter/endpoint), `AdaptiveRotation` (cap#5 score-driven), `GPUShuffle`/`EphemeralMemory`/`RAGSandbox` (cap#3), and the image/env/GPU mutation set (cap#1).
- `Baseline *BaselineSpec` — the digest-pin minimum + signature policy (cap#6).
- `MatcherMode` enum (`Exact` default | `Scored`) gating `D21`.

**STANDALONE CRDs** are reserved for the three objects whose lifecycle/restart-safety/observability genuinely exceed a spec field:

1. `WarmInferenceSet` (namespaced) — owns N warm pods + a leader-selecting Service; may wrap `sigs.k8s.io/lws`. This is where `D3`'s **primary** per-instance create-new-then-cutover durability lands.
2. `NodeRotation` (cluster-scoped) — models an in-flight drain so progress survives operator restart (corroborated by `SecurityEvent` itself being cluster-scoped).
3. `WorkloadBaseline` (the "Immutable Image Registry" as a distinct, GitOps-friendly object; AMTD carries `BaselineRef`).

`ContextMutationPolicy` is its own kind for ADA-Listing-1 fidelity but on the **operator group** `amtd.r6security.com/v1beta1` (see `D7g`), not the paper's literal `ADA.security.r6.dev/v1`.

**Precedence (locked):** a referenced CR, when present, **overrides** the embedded block of the same concern; `Status.effectiveSource` records which won. Embedded forms need only `make manifests` + `make generate`; standalone kinds register a scheme at `cmd/main.go` L53 and a reconciler above L131.

### The extended `AMTDAction` union (`MaxProperties=1`, all-pointer, comparable)

`AMTDAction` stays a kubebuilder `MaxProperties=1` tagged union (`adaptivemovingtargetdefense_types.go` L248-255). Today it is **all-pointer** (`Disable`/`Delete`/`Quarantine`/`Debugger`/`CustomAction`), which is why the L146 sentinel `action != (amtdv1beta1.AMTDAction{})` compiles and works. Existing members are preserved byte-for-byte; **four** new pointer members are added (each its own json-tagged `omitempty`):

```go
type AMTDAction struct {
    Disable      *DisableAction    `json:"disable,omitempty"`      // existing (was the L370 NOT-IMPLEMENTED slot)
    Delete       *DeleteAction     `json:"delete,omitempty"`       // existing cold rotation primitive (Client.Delete L198)
    Quarantine   *QuarantineAction `json:"quarantine,omitempty"`   // existing deny-all NetworkPolicy (L285-369)
    Debugger     *Debugger         `json:"debugger,omitempty"`     // existing (L204-241)
    CustomAction *CustomAction     `json:"customAction,omitempty"` // existing (L242-284)
    Rotate       *RotateAction     `json:"rotate,omitempty"`       // NEW caps#1/#3 mutating rotation (image/env/gpu/memory/RAG)
    WarmSwap     *WarmSwapAction   `json:"warmSwap,omitempty"`     // NEW cap#2 leader->warm-shadow cutover
    Regenerate   *RegenerateAction `json:"regenerate,omitempty"`   // NEW cap#6 restore-from-signed-baseline
    NodeRotate   *NodeRotateAction `json:"nodeRotate,omitempty"`   // NEW cap#7 panic-move to clean node
}
```

`MaxProperties=1` invariant (apiserver-enforced on the serialized object): **at most one** populated key; **zero** is also valid and is the in-Go no-match sentinel (a strategy whose `Action` has zero keys is a no-op that falls through to L370). Adding pointer members keeps the struct comparable, so the L146 `!=` sentinel is unchanged.

Every capability lands as one of these four new members **or** reuses an existing member: GPU shuffle / quarantine / ephemeral-memory / RAG / endpoint = `Rotate` overrides; drift self-heal = `Regenerate`; warm cutover = `WarmSwap`; node move = `NodeRotate`.

### The relaxed matcher — `D21` ScoredRuleMatcher

The bare `reflect.DeepEqual(strategy.Rule, securityEvent.Spec.Rule)` at `securityevent_controller.go` L139 is replaced with `MatchStrategy(strategy.Rule, ev.Spec)`. The L138-143 first-match loop and the L146 zero-value sentinel are **both preserved**.

**Predicate sketch (deterministic, per-strategy):**

1. **EXACT FAST PATH (default, backward-compat):** if `strategy.Rule.Match == nil && strategy.Rule.ScoreThreshold == nil`, evaluate equality of the **three-string projection** `{Type,ThreatLevel,Source}` of `strategy.Rule` against `ev.Spec.Rule`. The whole-struct `DeepEqual` is deliberately **narrowed** to the 3 strings so adding `Match` to one strategy cannot break a sibling exact strategy in the same AMTD.
2. **SCORED PATH:** if `Match` or `ScoreThreshold` is set, evaluate a **conjunction (AND)**: (i) every non-empty legacy string field of `strategy.Rule` must still equal `ev.Spec.Rule`'s same field (a `Source`/`Type` guard so a score clause cannot match unrelated events); AND (ii) every `MatchExpression` holds against `ev.Spec` (`anomalyScore` parsed via the `D19` `[0,1]` decimal; `metrics.<k>` from `SecurityEventSpec.Metrics`). `ScoreThreshold X` is exact sugar for `Match{Field:'anomalyScore',Op:'Gte',Value:X}`. A score clause vs. an event with `nil` `AnomalyScore` evaluates **false** (no panic, never selects).
3. **FIRST-MATCH-WINS** within `Strategy[]` order (unchanged L138-143 semantics).
4. **FEATURE FLAG:** scored evaluation lives behind per-AMTD `Spec.MatcherMode` (`Exact` default | `Scored`). In `Exact`, any `Match`/`ScoreThreshold` is **ignored** and a `Status` condition `type=MatcherModeWarning` warns that scored clauses are inert.

```go
type Rule struct {
    Type        string `json:"type"`        // existing
    ThreatLevel string `json:"threatLevel"` // existing
    Source      string `json:"source"`      // existing
    // +optional NEW (matcher-side only; emitters never set these on events)
    Match          []MatchExpression `json:"match,omitempty"`
    ScoreThreshold *string           `json:"scoreThreshold,omitempty"`
}
type MatchExpression struct {
    Field string `json:"field"` // 'type'|'threatLevel'|'source'|'anomalyScore'|'metrics.<k>'
    Op    string `json:"op"`    // Eq|NotEq|In|NotIn|Gte|Gt|Lte|Lt|Exists
    Value string `json:"value"` // scalar or comma-list; numeric ops parse decimal
}
```

**BYTE-COMPAT THEOREM (locked, per-strategy):** for any `(strategy.Rule, ev.Spec)` where `strategy.Rule.Match == nil && ScoreThreshold == nil`, `MatchStrategy` returns exactly what today's `reflect.DeepEqual` returns. Proof: today's whole-struct `DeepEqual`, when both Rules carry nil `Match`/`ScoreThreshold` (legacy CRs and legacy events both do), reduces to equality of `{Type,ThreatLevel,Source}` — identical to the 3-string projection. Verified emitters never populate event-side `Match`/`ScoreThreshold` (`prometheus-integrator` main.go L140-144 and `time-based-trigger` pod_controller.go L195-199 build `Rule` with only the 3 strings), so an event cannot perturb the projection. The guarantee is **per-strategy**: an exact strategy is evaluated exactly even when a scored strategy coexists in the same `Strategy[]`.

### Score representation + provenance — `D19` / `D26g`

- **`D19`:** `AnomalyScore *string` (decimal `'0'..'1'`, e.g. `'0.85'`) on `SecurityEventSpec`, **not** on `Rule` (keeps `Rule` a pure match key, preserving the exact fast path). Pointer/optional ⇒ `nil` is unscored = today's behavior; decimal-string avoids float canonicalization drift across JSON/etcd.
- **`D26g`:** the score is authoritative **only** when carried on the cluster-scoped, RBAC-gated `SecurityEvent.Spec.AnomalyScore` written by **trusted integrator ServiceAccounts**. Workload SAs **must not** be granted `securityevents` create/update; pod-annotation scores never drive rotation. A `StalenessWindow` decays old scores to `0` (neither suppression nor pinning survives staleness). Optional `:9443` admission webhook may enforce a trusted-`Source` allowlist.

### Mutation survival — `D3`

A mutation is durable **only** via (b) create-new-then-cutover (warm pool, per-instance — **primary**) or (a) patching the **top-level** owner template when the rotation is **workload-wide** (all replicas; never a bare ReplicaSet; guarded against the AMTD self-`Update` webhook loop). For (i) bare/unmanaged pods, (ii) Job-owned pods (`.spec.template` immutable), and (iii) per-pod panic events on a shared-template owner without a warm pool, durable per-pod mutation is **physically impossible** and `Status` records `mutation-not-durable` with reason (`BarePod|ImmutableJobTemplate|PerPodOnSharedTemplate`) — never silently lost or falsely claimed. `(a)` and `(b)` never both run on one pod (disjoint selectors).

### `ContextMutationPolicy` group — `D7g`

Kind `ContextMutationPolicy` on the **operator group** `amtd.r6security.com/v1beta1` (not the paper's literal upper-cased `ADA.security.r6.dev/v1`), as a **thin status reconciler**. Field shape stays faithful to Listing 1 (`Selector` + `Triggers.TelemetrySources[]` + `Mutations[]`). Triggers are realized by **emitting** SecurityEvents the matcher routes to a `Rotate` action. The `GatekeeperViolation` trigger is **unsatisfiable today** (no OPA-Gatekeeper audit emitter in any of the 5 repos) and is documented as a hard prerequisite/future work, never implemented-and-broken.

### Storm guard + cadence ownership — `D2`

- **Execution:** every mutating action (`Rotate`/`WarmSwap`/`Regenerate`/`NodeRotate`) is a **one-shot** executed by the responder for that action; `SecurityEventReconciler` dispatches `Rotate` (fills the L370-372 slot) and hands `WarmSwap`/`NodeRotate`/`Regenerate` to siblings. **No controller self-requeues to re-mutate.**
- **Cadence:** `time-based-trigger` is the **single jittered clock**; NIM's L131-132 self-requeue is demoted to pass-through (cold fallback only), so the same logical rotation is never double-jittered.
- **Storm guard (mechanized):** idempotence-by-construction + a min-interval + readiness gate + crash-loop backoff/rollback-to-last-known-good + EWMA-smoothed score requiring N consecutive high samples + a per-pod in-progress annotation (NIM early-returns on it).

### Status is the audit/feedback substrate

Both currently-empty `Status` structs (verified `struct{}` at `adaptivemovingtargetdefense_types.go` L284 and `securityevent_types.go` L45) are populated. No capability relies on an out-of-band side channel for observability. `AnomalyScore`/`Metrics`/`Evidence` are added to `SecurityEventSpec`; `Match`/`ScoreThreshold` to `Rule`; all pointer/`omitempty` so every emitter keeps compiling against the shared `github.com/r6security/phoenix/api/v1beta1` module. `make generate` regenerates deepcopy for **all** new embedded types; `make manifests` republishes the CRD schema.

## Decisions by theme

### Kernel

#### D1 — Config home (embedded vs standalone CRDs)

- **Paper basis:** [PAPER-CONTRADICTION → design decision]. ADA Listing 1 uses a **distinct** kind `ContextMutationPolicy`, apiVersion `ADA.security.r6.dev/v1` (a standalone-CRD pull). The operator's own group is `amtd.r6security.com/v1beta1` and the existing surface is `PodSelector` + `Strategy[]` only (an embedded pull). The corpus pulls both ways for the same config.
- **Options:** (a) embed all blocks on `AMTDSpec` (lowest surface, reuses enrollment/RBAC; cannot model an independently-lifecycled warm pool/node drain); (b) five standalone CRDs (faithful to Listing 1; heaviest, re-plumb enrollment); (c) hybrid (tuning embedded, heavy-lifecycle objects standalone).
- **Decision (OUR choice):** **(c) HYBRID.** Embed cadence/mutation/score blocks as optional pointers (`nil` ⇒ today's behavior); promote to standalone CRDs only `WarmInferenceSet`, `NodeRotation`, `WorkloadBaseline`. `ContextMutationPolicy` is its own kind but on the operator group (`D7g`).
- **Reasoning:** Embedding is the lower-surface default and lets `NIMReconciler` be **extended in place** (protects the one working trigger path). Standalone is reserved for objects the gap-spec independently argues need own lifecycle/restart-safety/observability.
- **Downstream commitments:** fixes embedded-vs-standalone for every capability; sets extend-in-place (NIM) vs new (WarmInferenceSet/NodeRotation/BaselineDrift); fixes the scheme/RBAC surface (`cmd/main.go` L53 scheme marker, L131 builder marker).
- **CRD/SecurityEvent expression:** neutral-to-supporting. Embedding keeps `Strategy[]` the single policy surface; standalone objects are still triggered via `Strategy[]` (`WarmSwap`/`NodeRotate`) — execution targets, not alternate trigger paths.

#### D2 — Which controller performs mutating rotation + storm-guard ownership

- **Paper basis:** [UNDERSPECIFIED → design decision]. Verified hazard: NIM self-requeues at fixed `RequeueAfter` (`nim_controller.go` L131-132, default 10s) and re-runs `processPodWithNIM` each tick (L126); a mutating version would re-mutate/re-delete continuously. No paper assigns controller ownership or a min-interval.
- **Options:** (a) NIM requeue loop owns mutating rotation (rotation-storms without a guard); (b) one-shot `RotateAction` in `SecurityEventReconciler` (idempotent, no built-in cadence); (c) hybrid split.
- **Decision (OUR choice):** **(c) HYBRID with explicit ownership split.** **Execution** = every mutating action is a one-shot in the action's responder; `SecurityEventReconciler` dispatches `Rotate` and hands off the rest. **Cadence** = `time-based-trigger` is the single jittered clock; NIM L131-132 demoted to pass-through. **Storm guard** = idempotence-by-construction + min-interval + readiness gate + crash-loop backoff/rollback + EWMA + N-consecutive-high + disjoint selectors/in-progress annotation. **Precedence:** an explicit `RotateAction` wins for that event; `Spec.InferenceRotation` governs scheduled cadence; `Status` records which fired.
- **Reasoning:** a one-shot executor removes the storm at its root; the single cadence owner resolves the double-jitter; keeping NIM as cold fallback protects the only end-to-end working path.
- **Downstream commitments:** caps #1/#3/#5 plug into the dispatch (one-shot), not the NIM loop; cap#4 jitter lives only in `time-based-trigger`; mandates the `D22` guard set; forces disjoint-selector coordination.
- **CRD/SecurityEvent expression:** directly **realizes Rule #1** — the `FindTimedEvent` gate becomes a `{Type:'timed',Source:'TimeBasedTrigger'}` → `{rotate}` strategy rule.

#### D3 — How image/env/gpu mutation survives recreate

- **Paper basis:** [UNDERSPECIFIED → design decision] (the single biggest fork). Both primitives delete the pod and the **owner** recreates from its existing template (`securityevent_controller.go` L198; `nim_controller.go` L168), so the replacement is byte-identical and any in-place mutation is lost.
- **Options:** (a) patch the owning controller's `PodTemplateSpec` (sticks, but fights GitOps/shared-template identity; impossible for Job); (b) create-new-then-cutover (warm swap; the only path delivering the availability claim; needs cap#2); (c) operator-owned wrapper (cleanest ownership, most invasive).
- **Decision (OUR choice):** **PRIMARY = (b)** create-new-then-cutover for enrolled inference workloads. **SECONDARY = (a)** owner-template patch, **restricted** to intentionally workload-wide rotations on the **top-level** owner (never a bare ReplicaSet, guarded against the AMTD self-`Update` loop). **FALLBACK** for bare/unmanaged pods, Job-owned pods (immutable template), and per-pod events on shared-template owners-without-warm-pool = today's delete-and-recreate, with `Status` `mutation-not-durable`+reason. `(a)` and `(b)` never both run on one pod.
- **Reasoning:** per-pod mutation on a shared Deployment template is **ill-posed** (no per-pod identity), so `(a)` is honestly scoped to workload-wide rotation only; Job/bare/per-pod-shared route to an explicit non-durability status rather than silently "sticking" a mutation that physically cannot stick.
- **Downstream commitments:** makes cap#2 a structural dependency of cap#1/#3 durability; defines the `MutationApplier` contract; requires the owner-walk helper + the self-`Update`-loop guard + an owner-kind classifier; adds the `mutation-not-durable`+reason `Status` field.
- **CRD/SecurityEvent expression:** supporting — whichever mechanism runs is invoked by a `Rotate`/`WarmSwap` action; `D3` only decides **how** the selected action is realized (or honestly reports it cannot be durable).

#### D21 — Relax the action matcher off Rule-equality

- **Paper basis:** [UNDERSPECIFIED → design decision], shape **mandated** by Rule #2. The L139 whole-`Rule` `DeepEqual` makes `AnomalyScore` structurally unreachable; ADA 6.3.3 wants score to select behavior, which the current matcher cannot express.
- **Options:** keep `DeepEqual` (violates Rule #2); add `ScoredRuleMatcher` behind a flag (backward-compatible, two paths); replace `DeepEqual` wholesale (one path, risk to every CR).
- **Decision (OUR choice):** **`ScoredRuleMatcher` behind a per-AMTD `Spec.MatcherMode` flag** (`Exact` default | `Scored`), realized as `MatchStrategy(strategy.Rule, ev.Spec)`. Exact fast path is outcome-identical to today's `DeepEqual` via the per-strategy byte-compat theorem; scored path is the conjunction described in the kernel. Legacy strings remain a guard in the scored path; `Exact` mode warns via a `Status` condition. Guarantee granularity is **per-strategy**.
- **Reasoning:** the minimal relaxation satisfying both clauses of Rule #2; the score-on-`Spec` (not `Rule`) split keeps the exact projection intact; emitters never set event-side `Match`/`ScoreThreshold` (verified), closing the only perturbation path.
- **Downstream commitments:** unblocks `D19`/cap#5; defines `Rule.Match[]`/`ScoreThreshold`; sets the evaluation order every conformance row relies on; records the per-integrator score-carrier prerequisite.
- **CRD/SecurityEvent expression:** **directly realizes Rule #2** — converts "a computed score/threshold selects an action" from impossible to a first-class `Strategy[]` expression.

#### D19 — AnomalyScore representation and home

- **Paper basis:** [UNDERSPECIFIED → design decision]. The papers name the signals (GPU entropy/query deviation/cache misses) and "proportional," but give no representation, range, or field location.
- **Options:** decimal string `'0'..'1'` on `Spec` (no float drift, keeps `Rule` pure); integer `0..100` (coarser); `resource.Quantity` (overkill); score on `Rule` (breaks the exact fast path).
- **Decision (OUR choice):** **`AnomalyScore *string` decimal `[0,1]` on `SecurityEventSpec`** (not on `Rule`). Pointer/optional ⇒ `nil` = unscored. Threat-reactive rotation keys via `Rule.Match{anomalyScore,Gte,X}` or `ScoreThreshold`. Range pinned `[0,1]`; panic default `0.85` is a flagged proposal (`D25`), not a paper value.
- **Reasoning:** keeping it on `Spec` preserves `Rule` as a pure match key (what `D21`'s fast path needs); a decimal string avoids float canonicalization instability across JSON/etcd; `[0,1]` matches "proportional to anomaly scores."
- **Downstream commitments:** fixes the field `prometheus-integrator` populates and the matcher parses; sets the `AdaptiveRotation` score source; pins the `D26g` trust-root object to a `Spec` field; requires additive falco/kubearmor extension if their scored rows need a magnitude.
- **CRD/SecurityEvent expression:** supporting — score-on-`Spec` + `D21` makes the magnitude reachable so a score selects an action via `Strategy[]`.

#### D26g — Score provenance / trust root (anti-forgery)

- **Paper basis:** [UNDERSPECIFIED → design decision]. Concrete inversion risk: a score arriving as a pod annotation/label lets a **compromised workload forge a low score** to suppress its own rotation. Papers name no transport or trust root.
- **Options:** `SecurityEvent.Spec.AnomalyScore` (cluster-scoped, RBAC-gated, integrator-written — recommended); pod annotation (spoofable, rejected); operator queries Prometheus directly (external dep + auth).
- **Decision (OUR choice):** **`SecurityEvent.Spec.AnomalyScore` as the canonical, RBAC-gated provenance**, written only by trusted integrator SAs. Pod-annotation scores are **disallowed as authority** (may be read for debugging, never drive rotation). A `StalenessWindow` decays old scores to `0`. Optional `:9443` validating webhook checks the creating SA is on a trusted-`Source` allowlist.
- **Reasoning:** RBAC makes the score unforgeable by the workload it describes (a stock workload SA has no `securityevents` create grant). **Residual risk:** the guarantee is exactly as strong as the RBAC binding, so the locked invariant additionally **requires** workload SAs **not** be granted `securityevents` create/update.
- **Downstream commitments:** mandates the RBAC; adds `StalenessWindow`; constrains `D20` to write via integrators; the optional admission webhook reuses `:9443`. A Source-guarded score rule additionally requires the named integrator to actually populate `AnomalyScore` (Prometheus does naturally; falco/kubearmor require additive extension).
- **CRD/SecurityEvent expression:** supporting/guard — every score-bearing trigger is a `SecurityEvent`, so provenance is enforced at the one contract object.

#### D7g — ContextMutationPolicy API group + reconciler-vs-data-only

- **Paper basis:** [PAPER-SPECIFIED] for **kind + field shape** (ADA Listing 1, confirmed); **[UNDERSPECIFIED → design decision]** for **group + reconciler-vs-data-only**.

### Scheduling & entropy

#### D5 — Cadence secrecy + restart-safety + which-timer-owns + stateful drain

- **Paper basis:** [UNDERSPECIFIED → design decision]. PHOENIX §III (read directly, p.2) mandates unpredictability ("any information the attacker gains from reconnaissance is immediately invalidated"; "unpredictability is the foundation of optimal defense"), which a published next-fire would defeat. Verified: `time-based-trigger` restores `lastRun` from the last `SecurityEvent` `CreationTimestamp` (`pod_controller.go` L144-148) and rejects pod-annotation state (L138-142). *The inference "a published next-fire defeats §III" is OUR reasoning, not a paper statement.*
- **Options:** (a) publish `NextRotationTime` + re-randomize on restart + double-jitter + drop in-flight (re-exposes the schedule, post-restart storm); (b) secrecy + persisted-seed + single owner + drain-before-delete; (c) public HMAC next-fire (attacker-computable).
- **Decision (OUR choice):** **(b).** **Secrecy:** `AMTDStatus` exposes only past cadence (`LastRotationTime`/`CurrentInterval`/`RotationCount`/`lastObservedScore`), **never** a next-fire; the sketched `NextRotationTime` field is **dropped** (or a debug-only opt-in, default off). **Restart-safety:** recover from last-fire (already durable in `SecurityEvent` etcd objects) **plus** a persisted per-AMTD jitter **Seed** so the in-flight offset is reproducible without a plaintext next-fire (≤1 extra rotation, no re-randomize). **Which-timer:** defer to the locked single cadence owner (`time-based-trigger`); NIM pass-through. **Stateful drain:** enrolled workloads route through `WarmSwap` (`D3` primary cut→drain→retire); cold `Delete`-path does LB-deregister + connection-drain over `GracePeriodSeconds` (reuse NIM 30s) before delete.
- **Reasoning:** secrecy is forced by PHOENIX §III; the persisted seed is the only way to get both restart-reproducibility and secrecy; re-randomizing risks the locked NO-ROTATION-STORM. Timer ownership is already locked, so honored not re-decided.
- **Downstream commitments:** drops `NextRotationTime` from the published schema; adds a per-AMTD persisted jitter **Seed** (**stored in a dedicated RBAC-gated Secret — NOT Status**, because `Status` is world-readable to anyone with `get` on the CR and would re-expose the secret cadence); makes `JitteredScheduler.Next` a pure function of `(seed, last-fire, podUID, policy)`; mandates connection-drain at the cold `Delete` site and `WarmSwap` drain for enrolled pods.
- **CRD/SecurityEvent expression:** supporting/guard — no new trigger path; cadence is still emitted as `{Type:'timed',Source:'TimeBasedTrigger'}` and matcher-selected.

#### D9 — Base rotation interval R and its hard floor

- **Paper basis:** [PAPER-CONTRADICTION → design decision]. AMTD-AI §3.2 (read directly, p.2) verbatim "`Default Rotation Interval R = 60 minutes ± jitter (10−30%)`"; the eval used 20-30m; the demo used 30s. Direction is pinned (smaller R + higher entropy minimizes ASR) but no single R is authoritative.
- **Options:** hard-code 60m / hard-code 20-30m / per-workload via CRD with default 60m + webhook floor / fully user-set (no floor, re-creates the storm).
- **Decision (OUR choice):** **per-workload `BaseInterval` (the existing Required `metav1.Duration`), default 60m** (AMTD-AI §3.2 verbatim). **Hard floor = 5m** enforced by the `:9443` validating webhook/CEL — explicitly **flagged a design proposal, not a paper figure**. The eval's 20-30m is a legal operator value above the floor; the 30s demo value is **rejected** in production (allowed only behind an explicit non-prod override). Same field+floor pattern for node-rotation `Interval` and telemetry `baselineInterval`/`minInterval`.
- **Reasoning:** a per-workload field with the white-paper value as default reconciles all three figures; the floor mechanizes the gap-spec's own warning that 10-30% jitter is meaningless on a 30s base and is the structural defense of NO-ROTATION-STORM at the cadence layer.
- **Downstream commitments:** pins default 60m + the floor (first real use of `:9443` for cadence validation); the same floor is the `D22` `minInterval` anti-flap gate; sets node/telemetry default+floor patterns. `JitterPercent==0` reproduces today's cadence bit-for-bit.
- **CRD/SecurityEvent expression:** supporting — R tunes **when** the single owner emits the timed `SecurityEvent`; the webhook floor is a validation guard, not a trigger path.

#### D10 — Jitter shape (band vs single, symmetric vs one-sided)

- **Paper basis:** **[PAPER-SPECIFIED].** AMTD-AI §3.2 verbatim "`R = 60 minutes ± jitter (10−30%)`". Two facts are specified: jitter is a **10-30% band** (never a single number), and `±` implies **symmetric**. The proposed "20" is the band midpoint, not a paper value.
- **Options:** single symmetric `JitterPercent` (not what the paper states); `JitterMin/MaxPercent` band, symmetric (faithful); one-sided downward (contradicts `±`); one-sided upward (strictly worse).
- **Decision (implement the paper):** **(b) symmetric BAND.** Replace the single `JitterPercent` sketch with `JitterMinPercent`/`JitterMaxPercent` (defaults `10`/`30` = the paper band endpoints, **not** the invented 20 midpoint). Per cycle the scheduler draws a magnitude `m ∈ [min,max]` and a symmetric sign so effective interval `= base*(1 ± m)`. A single symmetric `JitterPercent` is retained only as the degenerate `Min==Max` case (so `JitterPercent=0` reproduces deterministic cadence bit-for-bit). One-sided override is **rejected** (`±` is explicit).
- **Reasoning:** PAPER-SPECIFIED shape, so we implement the text; shipping a hard-coded 20 would violate the no-fabrication rule. Defaulting the band to its literal endpoints keeps every value traceable.
- **Downstream commitments:** replaces the single field; the webhook enforces `0 ≤ Min ≤ Max ≤ 100`; the band feeds the `D12g` distribution and is sampled via the `D13` crypto `RandSource` inside the single owner; sets the exposure-window bound `max-gap ≤ base*(1 + JitterMaxPercent/100)`. **Completion dependency:** fully realized only once `D12g` (distribution) and `D13` (RNG) land.
- **CRD/SecurityEvent expression:** supporting — jitter only perturbs **when** the single owner emits the timed event.

#### D12g — Distribution realizing the von Neumann mixed strategy

- **Paper basis:** [UNDERSPECIFIED → design decision]. PHOENIX §III (read directly, p.2) verbatim mandates "a mixed strategy — a probability distribution over all possible actions" and "unpredictability is the foundation of optimal defense" / "high-entropy implementation," but names **no specific distribution**.
- **Options:** (a) Uniform over the band (max Shannon entropy, simplest, zero invented params); (b) TruncatedNormal centered on R (lower entropy — concentrates mass; needs an invented stddev); (c) Exponential/Poisson (memoryless but unbounded, mismatched with a bounded ± band).
- **Decision (OUR choice):** **(a) Uniform as DEFAULT**, enum `Uniform;TruncatedNormal` (design-authored). `JitterDistribution` string on `RotationPolicy`, `+kubebuilder:validation:Enum=Uniform;TruncatedNormal`, default `Uniform`. `Scheduler.Next` draws the offset within the band using the selected shape; Uniform maps `RandSource.Float64()` onto the band.
- **Reasoning:** Uniform maximizes entropy over the bounded band — the only optimality criterion §III/§IV states — and needs **zero invented parameters** (TruncatedNormal needs a stddev the papers never give; Exponential needs a rate/mean). *"Uniform = max entropy over a bounded interval" is a mathematical fact attributed to OUR choice, not a paper statement.* TruncatedNormal retained as honestly-flagged lower-entropy opt-in.
- **Downstream commitments:** fixes the enum + the sampling contract inside the single jittered scheduler; constrains the predictability/entropy test (entropy of inter-rotation gaps near max for the band). `D10` supplies the band; `D9` the base R + floor.
- **CRD/SecurityEvent expression:** supporting — distribution shapes **when** `time-based-trigger` emits; the clock remains an emitter.

#### D13 — Entropy source (crypto vs seedable PRNG)

- **Paper basis:** [UNDERSPECIFIED → design decision]; security-load-bearing. Verified: the only `rand` in any repo is a non-security gRPC nonce (`kubearmor-integrator` `logClient.go` L84 `rand.Int31()`, `#nosec`); **no security RNG exists**. The kernel SINGLE CADENCE OWNER invariant already states "Cadence uses a crypto entropy source," which this decision concretizes.
- **Options:** (a) `crypto/rand` in prod (unpredictable, needs `RandSource` injection for tests); (b) seedable `math/rand` (predictable if seed leaks — inverts MTD); (c) hybrid enum `Crypto`(default)|`PseudoRandom`.
- **Decision (OUR choice):** **(c) HYBRID enum `EntropySource`** (`+Enum=Crypto;PseudoRandom`, default `Crypto`). Production entropy always comes from `crypto/rand` via the injectable `RandSource{Float64;Int63n;Read}`. `PseudoRandom` (seeded `math/rand`) is permitted **only** as an injected `RandSource` for test determinism; selecting it on a live AMTD records a `Status` condition `type=EntropyWarning`. The existing `math/rand` nonce is left untouched (non-security, out of scope).
- **Reasoning:** a leaked/low-entropy PRNG seed makes every future rotation forecastable, defeating the von Neumann unpredictability; defaulting to `Crypto` via DI gives prod unforgeable cadence while keeping tests deterministic without a weaker prod RNG.
- **Downstream commitments:** pins `RandSource` to `crypto/rand` in prod and as the test seam; the **same** `RandSource` feeds the `D12g` distribution **and** the `D14` stagger; adds the `EntropyWarning` condition; ties to `D5` (a CSPRNG clock is only as private as the schedule you publish).
- **CRD/SecurityEvent expression:** supporting/guard — entropy hardens the emitter clock; never a parallel trigger.

#### D14 — Stagger algorithm (avoid simultaneous fleet restarts)

- **Paper basis:** [UNDERSPECIFIED → design decision]. Proactive §V.A **Experimental Setup** (p.3) states the evaluation **used** "Staggered rotation to avoid simultaneous restarts" but gives no algorithm. (*Per the verdict: "used", not "requires" — the phrase sits in the evaluation setup, not a prescriptive design section.*) `hash(podUID) mod base` is design-authored.
- **Options:** (a) deterministic per-pod phase offset (`hash(podUID) mod BaseInterval` — de-syncs cheaply, restart-safe, but no concurrency cap); (b) independent per-pod jitter (max unpredictability, can still collide); (c) global `MaxConcurrentRotations` budget (hard cap, but leaves the schedule correlated); (d) combination.
- **Decision (OUR choice):** **(d) COMBINATION** with `StaggerMode` enum `PerPodPhaseOffset`(default)|`Independent`|`None` for the per-pod **de-sync**, layered with the crypto jitter (`D13`) for unpredictability and the separate `MaxConcurrentRotations` budget (`D24`) as the hard **availability cap**. `PerPodPhaseOffset` = `offset = hash(pod.UID) mod BaseInterval` inside `Scheduler.Next(now, key=pod.UID, policy)` (pure, restart-safe, no persistence); crypto jitter added on top. When the matcher would fire more than the budget at once, the executor defers the excess (the locked NO-ROTATION-STORM gate is the throttle). `hash(podUID)` is **flagged design-authored**.
- **Reasoning:** each single mechanism leaves a gap — phase offset de-syncs but doesn't cap; jitter randomizes but can collide; a budget caps but leaves the schedule correlated. The paper's words are an availability guarantee only the cap delivers; the high-entropy thesis wants the offset + jitter. Deriving the offset from the stable UID makes stagger restart-safe with zero new persisted state.
- **Downstream commitments:** binds `StaggerMode` to `Scheduler.Next`'s `key=pod.UID`; makes the `D24` budget the enforced cap (excess routed through the executor gate); shares the `D13` `RandSource`; for cap#7 the analogous `Stagger`+`MaxConcurrentNodes` enforce the no-mass-eviction invariant.
- **CRD/SecurityEvent expression:** supporting — staggering only modulates timing/concurrency of the same timed event; the concurrency cap is enforced in the one-shot executor (class-A), so no class-B reconcile gains a trigger.

#### D15 — Endpoint hash derivation + unforgeability + TTL value

- **Paper basis:** [UNDERSPECIFIED → design decision]. AMTD-AI §5 (p.6) verbatim "Randomized endpoint URLs with hash-based TTL" and §5.3 (p.8) "Custom TTL for model services" name a hash-based TTL but no hash function, input, key, transparency log, or numeric TTL. The `SHA256;HMAC-SHA256` enum and `PathTemplate '/{hash}'` are design-authored.
- **Options:** (a) `SHA256(seed||epoch||podUID)`, seed in Secret (unforgeable only if seed stays secret); (b) `HMAC-SHA256(key, epoch||podUID)` (cryptographically unforgeable without the key; adds a key trust root); (c) random UUID per rotation (unguessable but not restart-reproducible); (d) defer generation, own only TTL.
- **Decision (OUR choice):** **(b) HMAC-SHA256 as DEFAULT**, with (a) SHA256 as a lower-assurance enum option. `HashAlgorithm` enum `HMAC-SHA256`(default)|`SHA256`; HMAC requires `KeySecretRef` (webhook-enforced). Derivation: `HMAC-SHA256(key, BaseInterval-epoch || podUID || rotationCounter)` → hex into `PathTemplate` (default `'/{hash}'`). `TTL` is a separate `EndpointRotationPolicy.TTL` (`metav1.Duration`) defaulting to `== BaseInterval`, with `JitterTTL` reusing the cap#4 Jitterer and an **overlap-grace** window (default `== GracePeriodSeconds`, 30s) during which both old and new paths resolve. Numeric TTL is operator-set (no paper value); webhook floor mirrors `D9`.
- **Reasoning:** only a keyed MAC answers the forgeability requirement (attacker must not compute the next path); keying off `epoch||podUID||counter` (not wall-clock) keeps the path reproducible after restart while unguessable; `TTL==BaseInterval`+grace lets the path live exactly as long as the instance and protects in-flight draining. Key is a Secret (`D26g`/`D20g` posture), never published.
- **Downstream commitments:** pins the fields on `EndpointRotationPolicy`; adds `secrets get` RBAC to the Rotate executor only when HMAC selected; `CurrentEndpointHash` to `Status`, key/seed never published; webhook validates "HMAC ⇒ `KeySecretRef` set."
- **CRD/SecurityEvent expression:** the derived path is produced by the `Rotate` responder at execution time; no new `Strategy[]` entry — derivation is a property of how the selected action realizes cutover.

#### D16 — Endpoint rotation scope (in caps #1/#2/#4 vs separate)

- **Paper basis:** [PAPER-CONTRADICTION → design decision]. AMTD-AI §3.2 "endpoint path … rotated" + §5 "Randomized endpoint URLs" (the URL **changes**) vs AMTD-AI §5 "Majority expose static endpoints via LoadBalancer or Ingress" + Proactive §IV.D step 5 "Update Service Endpoints **without interrupting client connections** (leveraging Kubernetes Service abstraction)" (client-facing endpoint **stable**). *(The tension is reconcilable as two layers — a rotating backend behind a stable front — so this is the conservative framing.)*

#### D24 — Cluster-wide concurrency / availability budget

- **Paper basis:** [R6-PAPER-ONLY]. Proactive §V.A (p.3) verbatim "Staggered rotation to avoid simultaneous restarts," "Cluster Size: 400 nodes," "Tested up to 50,000 container instances … without downtime," and §IV.E "Cost Efficiency: Overhead … between 1-2% of cloud compute cost." The **99.8% availability** and **1.3-1.7% overhead** figures are verbatim in the adaptive-container-orchestration **abstract (p.1)** — asserted results with no measurement methodology, depending on an unstated concurrency limit.

- **Decision (OUR choice):** **(a) `MaxConcurrentRotations *int` per AMTD as PRIMARY**, enforced as a **semaphore** in the one-shot executor/Staggerer: a matched `Rotate`/`WarmSwap`/`NodeRotate` proceeds only if in-flight rotations under that AMTD `< MaxConcurrentRotations`, else the `SecurityEvent` is **requeued** (`ctrl.Result{RequeueAfter}`), **not dropped**. **Complemented by (c):** respect an optional PDB when one covers the workload. The 1.3-1.7%/99.8% numbers are R6-PAPER-ONLY targets this budget silently relies on, asserted with no measurement code.
- **Downstream commitments:** activates `MaxConcurrentRotations`; adds the semaphore/Staggerer gate (shared with `D14`); requeue-on-full; optional PDB lookup; throttle reason + in-flight count to `Status.conditions`; pins 1.3-1.7%/99.8% as targets-to-confirm with no benchmark code.
- **CRD/SecurityEvent expression:** not an action and not a trigger path — an execution-time throttle on already-selected actions; a budgeted-out action is requeued, so every action stays `Strategy[]`-expressible.

### Image trust & signing

#### D6 — Trust root, signature scheme, comparison surface, fail mode

- **Paper basis:** [UNDERSPECIFIED → design decision]. AMTD-AI 3.1 names only a "Golden Image Repository: Immutable, signed copies"; Proactive IV.B an "Immutable Image Registry" storing "trusted, signed" images; README L34 "cryptographically signed baseline." No scheme, signer, key, transparency log, comparison surface, or fail mode. Verified: cosign/sigstore/rekor/fulcio appear in **zero runtime Go** (cosign exists only in a `prometheus-integrator` CI workflow); the only shipped drift detection is two Falco rules, both `enabled:false`.
- **Options:** cosign key-based (offline, smallest trust root, deterministic); cosign keyless (Fulcio+Rekor, online dependency, overkill air-gapped); Notation/SLSA (new dep surface, needs a build pipeline); digest-allowlist only (no supply-chain guarantee); comparison surface = full PodSpec/Falco (false-positive drift / detection-only).
- **Decision (OUR choice):** **DEFAULT = cosign KEY-BASED, split fail mode, comparison surface = image DIGEST + a curated mutable-field allowlist (NOT full PodSpec).** `SignaturePolicy{PublicKeyRef(Secret/KMS), KeylessIdentity{Issuer,SubjectRegexp} (optional), RekorURL (optional), RequireSignature(default true)}`. Verification runs at **both** points: (1) `baselineAdmission` webhook on `:9443` = **FAIL-CLOSED** (unsigned/unverifiable/wrong-digest image **denied** synchronously at create/update); (2) `BaselineDriftReconciler` poll + verify-before-recreate at L168/L198 = **FAIL-TO-CACHED-LAST-GOOD-WITH-GRACE** (a registry/Rekor blip does **not** mass-flag drift or block recreate; reuse the last verified digest, surface `VerificationUnavailable`; only a positive signature/digest **mismatch** is drift). Falco fs/exec drift stays **detection-only** (emits a drift `SecurityEvent`, does not gate admission). The `@sha256` digest assertion is a **soft validating-WARN default**, never a hard CRD regex. **Carried caveat (locked, in docs + Status): signing proves PROVENANCE/INTEGRITY, NOT BENIGNITY** — a validly-signed-but-backdoored upstream image (SolarWinds shape) passes; digest-allowlist-only gives no supply-chain guarantee. Keyless/Notation/SLSA are documented upgrade paths, not v1.
- **Reasoning:** cosign key-based is the minimum satisfying "cryptographically signed" while staying offline-capable and reusing the one verification library already in CI. The **split fail mode** is the crux: admission must fail-closed (an unsigned image must never be admitted), but a background poll must **not** fail-closed on transient unavailability (that converts a network blip into a mass false-positive drift storm / self-heal DoS and fights GitOps). Digest+allowlist (not full PodSpec) avoids the near-zero-false-positive failure the proof gate forbids.
- **Downstream commitments:** pins `SignaturePolicy` on `BaselineSpec` and the `BaselineVerifier` impl to a cosign Go-API + go-containerregistry resolver (**NEW runtime deps**; cosign was CI-only). Fixes the two call sites (`baselineAdmission` fail-closed, needs a new `ValidatingWebhookConfiguration` + certs; `BaselineRestorer.Regenerate` fail-to-cached-last-good before L168/L198). Adds `Status` conditions `VerificationUnavailable`/`DigestUnpinnedWarning`/`SignatureMismatch` and `BaselineStatus.PinnedDigests`/`LastVerifiedTime`. RBAC: `secrets get;list;watch` + `validatingwebhookconfigurations` when admission-enforced.
- **CRD/SecurityEvent expression:** **realizes Rule #1** — the verification surface is the `BaselineDriftReconciler` **emitter** (emits `SecurityEvent{Rule.Type='drift', Evidence}`, does not act directly); the matcher routes via the exact fast path on the literal `{type:'drift',source:'FalcoIntegrator'}` 3-string rule to the `Regenerate` action (needs no scored matching, no score-carrier extension). The admission webhook is a synchronous **guard**, not an action.

#### D6g — Baseline storage, desired-state source, GitOps precedence, detection cadence, default response, hardening reset, SecurityEvent contract

- **Paper basis:** [UNDERSPECIFIED → design decision]. AMTD-AI §3.1 "Golden Image Repository"; Proactive §IV.B "rollback to last known-good"; §IV.C.4 "Each container rotation mutates its runtime hardening profile (Seccomp, AppArmor, RBAC policies)"; README L34 self-heal. No storage location, desired-state source, GitOps precedence, scan interval, default-response choice, or hardening-reset **scope**. Only shipped detection is two Falco Container-Drift rules, both `enabled:false`, wired to no restore loop.
- **Options:** storage — external immutable signed registry + offline-signed digests (CRD holds references only) vs full in-cluster Secret/CRD snapshot (mutable, reopens tamper inversion). Source — regenerate from a Phoenix-owned snapshot via owner-walk. GitOps — single-healer annotation, yield-to-Argo/Flux. Detection — admission + Falco events + optional poll. Default response — Regenerate (restart-loop-DoS-weaponizable) vs Quarantine+alert vs AlertOnly vs Block-at-admission. Hardening reset — pod-local triple vs also RBAC. Contract — extend `SecurityEvent` with `Evidence`.
- **Decision (OUR choice):** **(a) STORAGE** = external immutable signed registry + **offline-signed digests**; the standalone `WorkloadBaseline` CRD (and embedded `BaselineSpec`) carry **only references** (`ImageDigestRef`, `SignaturePolicy` key/Rekor refs, optional `PodSpecSnapshotRef`) + `BaselineStatus.PinnedDigests`, **never** the trust-root secret. **(b) SOURCE** = regenerate from a Phoenix-owned snapshot/verified digest via `BaselineRestorer.Regenerate` owner-walk to the TOP owner template **before** the L168/L198 delete (guarded against the AMTD self-`Update` loop); bare/Job/per-pod-shared route to cold fallback with `mutation-not-durable`+reason. **(c) GITOPS** = explicit precedence annotation (e.g. `amtd.r6security.com/healer`) names the single healer; default when a GitOps owner is detected is **YIELD** (detect + emit `Evidence` + admission-Block), **not** re-patch (never fights ArgoCD/Flux, which are external to the 5 repos); `BaselineStatus` records the effective healer. **(d) DETECTION+RESPONSE** = admission (`baselineAdmission` `:9443`) + Falco Container-Drift events (the two `enabled:false` rules **turned on** and the falco-integrator **extended** to map their rule-name → `Type:'drift'`); periodic poll is an **optional `DriftPolicy.DetectInterval`** (no paper value, **off by default**). **DEFAULT `OnDrift = Quarantine+alert`** (**NOT** auto-Regenerate, because Regenerate is weaponizable into a restart-loop DoS); Regenerate is fully supported but inherits the `D2` one-shot + `D22` min-interval/readiness/crash-loop-backoff/rollback guards **and** the `D24` `MaxConcurrentRotations` budget. `AdmissionEnforce` default `true`. **(e) HARDENING RESET** = reset `securityContext` + Seccomp + AppArmor to baseline by default (a **DESIGN DECISION motivated by §IV.C.4's hardening-profile-mutation theme** — §IV.C.4 specifies that rotation *mutates* those profiles, it does **not** specify a reset-to-baseline-on-regenerate); RBAC RoleBinding reset is **opt-in** (`ResetHardeningProfile` = `PodProfileOnly`(default)|`IncludeRBAC`), deferred-by-default due to blast radius. **(f) CONTRACT** = extend `SecurityEventSpec` with `Evidence *DriftEvidence{ObservedDigest,ExpectedDigest,Detail}` and populate `BaselineStatus`; drift flows through the same matcher (exact `Type:'drift'` fast path), never a private channel.
- **Reasoning:** the defense is only as strong as where the baseline lives, so the trust root is pushed out of mutable cluster state into an offline-signed external registry. Regenerating from a Phoenix-owned snapshot is what makes "forcibly restarted from golden state" true rather than redeploying tampered live state. ### Warm-pool / LWS swap

#### D11 — "Warm"/"ready in RAM" definition, pool size N, LWS-vs-in-tree, config home

#### D12 — Traffic-steering primitive (leader→shadow cutover)

- **Paper basis:** [UNDERSPECIFIED → design decision]. AMTD-AI §3.1 (read directly, p.2): "Inference Load Balancer: Routes traffic to active leader based on health and schedule." That single sentence is the only mechanism statement; no Kubernetes primitive, atomicity/draining semantics, or RBAC. The `EndpointSwap;ServiceSelectorSwap;GatewayWeight;LeaderLabel` enum is **entirely design-authored**.
- **Options:** `ServiceSelectorSwap` (move a leader label a Service selects — portable, least privilege, sub-second propagation); `EndpointSwap` (rewrite EndpointSlice — fastest, more privileged, fights the Endpoints controller); `GatewayWeight` (HTTPRoute weights — graceful, needs Gateway API); `LeaderLabel`-only (external LB/mesh re-points — weakest correctness).
- **Decision (OUR choice):** **DEFAULT = `ServiceSelectorSwap`**, realized behind the `TrafficSteerer.CutTraffic` interface as `TrafficCutStrategy` enum (`EndpointSwap;ServiceSelectorSwap;GatewayWeight;LeaderLabel`, **design-authored**). `WarmInferenceSet` owns a leader-selecting Service; the 5-step swap = (1) mark the warm shadow Ready (`D11` gate), (2) **atomically move the leader label** so the selector resolves to the shadow, (3) wait `DrainTimeoutSeconds` (default reuse NIM grace 30s) for in-flight, (4) retire the old leader, (5) `WarmPoolManager.EnsurePool` re-warms a replacement from the golden image. - **Reasoning:** `ServiceSelectorSwap` works on a stock cluster with least privilege and no external dependency, so the capability lands without forcing a mesh/Gateway install. The full enum is pluggable so Gateway-API users can opt into weighted draining. The Ready-before-flip + drain-before-retire ordering is what actually delivers near-zero-downtime — a design rule, not a paper value.
- **Downstream commitments:** adds `TrafficCutStrategy` (default `ServiceSelectorSwap`) + a leader-selecting Service the controller owns; pins the `TrafficSteerer.CutTraffic` contract and the 5-step `Swap` (relocating the NIM L168 cold `Delete`); RBAC strategy-dependent (`pods/patch`+`services` always; `endpointslices/update` for `EndpointSwap`; `httproutes/update` for `GatewayWeight`); cutover timing → `Status.warmPool.lastSwapDurationMillis`.

#### D19g — What 'encrypted' means in encrypted ephemeral memory volumes

- **Paper basis:** [UNDERSPECIFIED → design decision]. Proactive §IV.C item 5 (read, p.3) "disposable encrypted memory volumes with unique, random keys. Keys are destroyed at container termination"; ADA §5.6.1 (read, p.13) "encrypted ephemeral volumes … rotated and re-keyed on every inference cycle." No cipher, key length, keystore, or trust root. Technical fact: tmpfs (`emptyDir medium=Memory`) is memory-**resident** but **not** cryptographically encrypted; real crypto needs dm-crypt/LUKS or a CSI driver; TEE/confidential-VM is hardware and ADA §6.3.4 (read, p.14, under §6.3 Future Work) explicitly **defers** it. `KeySourceRef` leaves `CipherSuite`/`KeyBytes` open.
- **Options:** (a) tmpfs only (fast, no crypto, weak vs root — would mislabel itself "encrypted" without a disclaimer); (b) LUKS/dm-crypt init container (real crypto, needs privileged init, fights unprivileged PSS); (c) CSI transparent at-rest (real crypto, unprivileged, needs a CSI driver, on-disk); (d) TEE/SEV-SNP/TDX (defends a privileged co-resident, hardware-gated, §6.3.4-deferred).
- **Decision (OUR choice):** **honest enum `EphemeralMemoryPolicy.Medium`** with a non-misleading contract. `Medium: 'Memory'(DEFAULT, tmpfs)|'Disk'(CSI)`. **`Memory`** = tmpfs `emptyDir` — explicitly documented as **memory-resident + disposable + per-rotation freshly-keyed scratch but NOT cryptographically encrypted at the block layer**; its security property is **ephemerality + key destruction on termination** (the lifecycle §IV.C.5 actually stresses), NOT confidentiality vs a root/hypervisor adversary. **`Disk`** = CSI transparent at-rest encryption (real crypto) when the cluster provides an encrypting CSI driver. **TEE/confidential-VM is NOT implemented** and is documented as the ADA §6.3.4-deferred hardware path that alone covers the privileged co-resident threat (ties to `D23g`). `KeySourceRef` stays kernel-locked: `CipherSuite`/`KeyBytes` **left open** (no invented cipher/length). A `Status` condition surfaces the effective confidentiality tier (`EphemeralOnly`|`AtRestEncrypted`|`TEE-NotAvailable`) so no caller mistakes tmpfs for cryptographic encryption.
- **Reasoning:** the papers say "encrypted" but specify no cipher/keystore/trust-root and tmpfs is not crypto; we refuse to label the default cryptographically encrypted, instead delivering the property the paper genuinely emphasizes (disposable + unique-random-key + destroyed-at-termination), exposing a real-crypto tier (CSI) for clusters that have it, and deferring TEE exactly where ADA §6.3.4 does.
- **Downstream commitments:** sets `Medium` enum embedded on `InferenceRotationSpec`; binds `EphemeralKeyManager.ProvisionKey/DestroyKey` with the destruction-race guard; keeps `KeySourceRef{CipherSuite,KeyBytes}` open; adds `lastKeyID`/`rekeyCount` + the effective-tier condition; declares TEE deferred; CSI path adds `storage.k8s.io` RBAC only when `Medium=Disk`; threat model scoped to unprivileged co-resident for the default.
- **CRD/SecurityEvent expression:** supporting — the ephemeral-memory volume is provisioned as part of a `Rotate` action's overlay, e.g. `{rotate:{overrides:{ephemeralMemory:{medium:'Memory',rekeyOn:'Rotation'}}}}`; the matcher selects the rotation; volume/key lifecycle is realized by the action.

#### D20g — Ephemeral key source, trust root, destruction (destruction-race guard)

- **Paper basis:** [UNDERSPECIFIED → design decision]. Proactive §IV.C item 5 (read, p.3) — keys are "destroyed at container termination," the crux. No keystore, cipher, key length, or trust root; `CipherSuite`/`KeyBytes` left open (invention guard).
- **Options:** (a) per-pod operator-generated K8s Secret + finalizer `DestroyKey` + ownerRef GC (zero external dep, reuses plumbing, but API/etcd-readable — weaker root; needs the race guard); (b) external KMS/Vault short-TTL lease (strongest root, key never in etcd, TTL auto-destroys; hard external dep, greenfield); (c) SPIFFE/SPIRE or TEE-sealed (per-workload identity / hardware sealing, largest scope, hardware-gated/§6.3.4-deferred).
- **Decision (OUR choice):** **`KeySourceRef.Type` enum `{GeneratedSecret(default, dev/low-trust)|KMS|Vault|TEESealed}`** behind `EphemeralKeyManager`, with **KMS/Vault short-TTL as the RECOMMENDED production trust root** and `GeneratedSecret` as the zero-dependency default. `CipherSuite`/`KeyBytes` pass-through with **no operator-chosen default**. **DESTRUCTION-RACE GUARD (locked, the crux):** (1) the fresh Secret's `ownerReference` is bound to the **NEW** (replacement/shadow) pod, not the dying pod, so K8s GC never collects the live key; (2) `DestroyKey(oldKeyID)` runs **only AFTER** the replacement is keyed-and-Ready — sequenced through `D2`'s readiness gate and `D3`'s cut→drain→retire→re-warm ordering — so the foreign-controller-recreated replacement always has keyID-B before keyID-A is destroyed; (3) for KMS/Vault, the old lease is revoked post-cutover (or allowed to TTL-expire within the grace window); (4) `DestroyKey` is **idempotent and keyed by keyID** so a re-reconcile after restart neither double-destroys nor leaks. `lastKeyID`/`rekeyCount` → `Status`.
- **Reasoning:** an enum keeps the invention guard intact (never pick a cipher) while letting the trust root scale dev→hardened, mirroring `D26g` (an in-band, workload-readable carrier is a weak root). The destruction race is the part the paper calls "the crux"; resolving it by **reusing `D2`'s readiness gate and `D3`'s cutover ordering** (destroy-after-Ready, own the Secret to the new pod) means no new machinery and provably no window where the live replacement is keyless. TEE-sealed is offered but §6.3.4-deferred.
- **Downstream commitments:** adds `KeySourceRef{Type enum;SecretRef/KMSKeyRef/VaultPath;CipherSuite string;KeyBytes int}` (no default cipher); wires `ProvisionKey/DestroyKey` into the `D2` Rotate branch / `MutationApplier`; mandates Secret ownerRef target = NEW pod + `DestroyKey`-after-Ready as a hard invariant on every ephemeral-volume path; pins `lastKeyID`/`rekeyCount`; records KMS/Vault as recommended-but-optional and TEE-sealed as deferred; requires RBAC such that workloads cannot read other workloads' key Secrets.
- **CRD/SecurityEvent expression:** supporting/guard — key provisioning/destruction is a side-effect of an already-matched `Rotate`/`WarmSwap` action; nothing about keys is reachable outside the matcher.

#### D21g — Mapping ADA 're-key on every inference cycle' to K8s

- **Paper basis:** [UNDERSPECIFIED → design decision]. ADA §5.6.1 (read, p.13, "Short-Lived Checkpointing" bullet — distinct from the "Runtime RAG Sandbox" bullet, `D24g`) verbatim "Stateful agent memory is written to encrypted ephemeral volumes, which are rotated and re-keyed on every inference cycle." A pod-operator has **no visibility into individual inference requests**; it can only act on pod rotation/reconcile.
- **Options:** (a) approximate "inference cycle" as "pod rotation" (operator-only, document the gap); (b) operator provisions an in-pod re-key sidecar it does **not** drive (greenfield component the operator can't control); (c) require the model server (NIM/vLLM) to re-key itself, operator only provisions the volume+key (truest to per-cycle, but a server contract not an operator guarantee).
- **Decision (OUR choice):** **`rekeyOn` enum `{Rotation(default)|InferenceCycle}`** that makes the un-observable cadence **explicit** rather than faked. **`Rotation`** (default, operator-only): the operator re-keys via `ProvisionKey` at each matched rotation — the only event boundary a pod-operator can observe — and `Status.rekeyCount` counts rotations; the granularity gap vs the paper's literal per-request claim is **documented, not hidden**. **`InferenceCycle`** (opt-in delegation): the operator still only **provisions** the keyed volume/key material; true per-request re-keying is **delegated to the model server**, recorded as a model-server contract/prerequisite (and a `Status` condition warning when no cooperating server is detected) — never asserted as an operator-enforced guarantee. The operator-provisioned sidecar (option b) is offered as a future realization of `InferenceCycle`, not the landed default.
- **Reasoning:** the paper asserts per-cycle but a pod-operator cannot observe a cycle, so defaulting to `Rotation` is the only mapping the controller can honestly guarantee; labeling the field makes the impedance mismatch first-class. `InferenceCycle` preserves fidelity to §5.6.1 but is scoped to delegation with an explicit prerequisite/warning, consistent with flagging unmet dependencies rather than shipping them implemented-and-broken. The per-cycle text is preserved verbatim as the `InferenceCycle` intent (no paper claim invented).
- **Downstream commitments:** adds `rekeyOn` to `EphemeralMemoryPolicy` (default `Rotation`); ties `Rotation`-mode re-key to the same `D2`/`D3` rotation moment as `D20g`'s `ProvisionKey`; records `InferenceCycle` as requiring a cooperating model server (status condition when absent); defines `rekeyCount` semantics; leaves the sidecar as future work.
- **CRD/SecurityEvent expression:** supporting — re-keying happens at the rotation the matcher already selected; `rekeyOn` only chooses **who** re-keys; `InferenceCycle`'s per-request re-key is the model server's internal behavior, outside Phoenix's action surface.

#### D23g — Privileged-vs-unprivileged co-resident threat model

- **Paper basis:** [UNDERSPECIFIED → design decision]. ADA Listing 1 gives only software primitives (tmpfs, gpu '0', `RUNTIME_MODE=SECURE`) and ADA §6.3.4 "Integration with Confidential Computing" (read directly, **p.14**, under §6.3 Future Work) explicitly **defers** hardware isolation: "ADA can be adapted to run within confidential computing environments such as Intel SGX or AMD SEV … addressing advanced threat scenarios, including insider attacks or host compromise." Proactive §III.C.4 names the privileged vectors (shared memory / cache timing / PCIe bus). The papers fix **which** adversary TEEs are needed for but never decide the boundary the **software** layer claims.
- **Options:** (a) scope software primitives to the **unprivileged** co-resident adversary only; declare privileged/host/hypervisor out-of-scope (TEE-deferred), record residual risk in `Status` (honest, matches §6.3.4, zero hardware dep); (b) claim protection against the privileged adversary now (implement SEV-SNP/TDX — hardware dep ADA itself defers, huge greenfield, fabricated capability); (c) ship tmpfs+Secrets with no boundary statement (defense-inversion: an operator assumes "encrypted ephemeral memory" resists root and is silently exposed).
- **Decision (OUR choice):** **(a).** Software cap#3 primitives (tmpfs, RBAC-gated Secrets/keys, deny-all NetworkPolicy RAG isolation) are scoped to the **unprivileged** co-resident adversary (peer pod / same-namespace tenant / non-root sidecar). The **privileged** adversary (node-root / host / hypervisor / insider with PCIe/cache-timing access) is declared **out of scope** and routed to a future TEE path. Add a forward-compatible **inert** optional pointer `ConfidentialComputing *ConfidentialComputingPolicy{RuntimeClassName string; RequireAttestation bool; Provider enum(SEV-SNP,TDX,SGX)}` on `InferenceRotationSpec` that is **inert today** (`nil` ⇒ software-only) and reserves the §6.3.4 seam without implementing it. `AMTDStatus` surfaces a `threatBoundary` condition (`{coResidentScope:'Unprivileged', privilegedAdversary:'OutOfScope-TEEDeferred'}`). `EphemeralMemoryPolicy.medium=Memory` (tmpfs) is documented as "memory-resident, NOT cryptographic vs root" (ties to `D19g`).
- **Reasoning:** the papers are silent on the boundary but pin the deferral (§6.3.4: TEEs are future work), so claiming privileged-adversary resistance now would fabricate a capability with no code. Scoping to the unprivileged adversary is the only honest posture — the software primitives DO measurably raise cost for a co-tenant pod (deny-all NetworkPolicy verified L285-369; tmpfs leaves no disk artifact; Secrets RBAC-gated). Recording the boundary in `Status` prevents defense-inversion.
- **Downstream commitments:** sets the honest-scope envelope for `D19g`/`D20g`/`D24g`; adds the inert `ConfidentialComputing` pointer + deepcopy/manifests + the `threatBoundary` condition; forbids any conformance row from asserting confidentiality vs root/host. No new controller, no new trigger path.
- **CRD/SecurityEvent expression:** neutral/guard — a threat-model scoping decision, not a workload effect, so **not** a `Strategy[]` entry. The inert `ConfidentialComputing` field, if ever implemented, would ride the same `Rotate` action (a runtimeClass overlay), never a parallel path.

#### D24g — RAG Sandbox isolation primitive + data-exposure TTL

- **Paper basis:** [UNDERSPECIFIED → design decision]. ADA §5.6.1 (read, p.13, "Runtime RAG Sandbox" bullet) "RAG components run in isolated pods with limited time-bound data exposure" — names **isolation** and a **time bound** but specifies no mechanism and no TTL value. The deny-all NetworkPolicy primitive exists and works (`securityevent_controller.go` L285-369: empty Ingress/Egress + both PolicyTypes + pod relabel + AMTD owner-ref).
- **Options:** (a) reuse the deny-all NetworkPolicy primitive as the default RAG isolation + optional namespace pinning; TTL drives a re-key/rotate via the standard emit-then-match path (reuses verified owner-ref'd code, TTL flows through the single cadence owner, cheapest; network-only, same-node root out of scope per `D23g`); (b) gVisor/Kata runtimeClass (stronger syscall isolation, cluster dep, greenfield); (c) dedicated namespace only (no network/data isolation alone — collapses into (a)).
- **Decision (OUR choice):** **(a) reuse the deny-all NetworkPolicy primitive** (L285-369) as the default isolation, optionally combined with namespace pinning; runtimeClass (gVisor/Kata) is an **optional hardening overlay**, not the default. `RAGSandboxPolicy` is an embedded pointer on `InferenceRotationSpec` (`D1`): `RAGSandboxPolicy{Isolation enum(DenyAllNetworkPolicy(default),Namespace,RuntimeClass); RuntimeClassName string; NamespaceRef *LocalRef; DataExposureTTL metav1.Duration}`. `DataExposureTTL` has **no paper value** → a **flagged proposal default (e.g. 15m), explicitly a design proposal not a paper number**, tunable. TTL is **not a hidden timer**: it is realized by `time-based-trigger` (the sole jittered cadence owner) emitting a `SecurityEvent` the matcher routes to a `Rotate` action whose overlay re-keys the ephemeral volume and recreates the RAG pod (rotate-and-re-key "on every inference cycle" approximated as per-TTL, consistent with `D21g`). The isolation NetworkPolicy is applied via a **factored `applyDenyAllNetworkPolicy` helper** shared by the `Quarantine` action and the RAG `Rotate` overlay (it is a separate cluster object, **not** folded into the `MutationApplier.Apply(podSpec,…)` contract).
- **Reasoning:** reusing the verified deny-all NetworkPolicy (rather than inventing an isolation engine) is the lowest-surface faithful realization of "isolated pods" and reuses tested code. Tying the TTL to the existing single-cadence emit-then-match path keeps Rule #1 intact and reuses the storm-guarded one-shot Rotate executor. runtimeClass adds a cluster dependency ADA doesn't require and only partially helps against the privileged adversary `D23g` already scopes out. The TTL value is honestly flagged as a proposal. *(The paper's "rotated and re-keyed on every inference cycle" clause attaches to the encrypted ephemeral **volumes**, which the RAG re-key overlay rotates/re-keys.)*
- **Downstream commitments:** adds embedded `RAGSandboxPolicy` + deepcopy/manifests; binds RAG isolation to the **same** deny-all NetworkPolicy code as `Quarantine` (factored helper); the RAG re-key reuses the `EphemeralMemoryPolicy` key source (`D20g`) and the shared `MutationApplier` (`D3` routing); `time-based-trigger` supplies the TTL cadence; `AMTDStatus` records `ragSandbox{activeNamespace,lastRekeyTime,isolationApplied}`.
- **CRD/SecurityEvent expression:** **realizes Rule #1** — RAG isolation+TTL is `{rule:{type:'timed',source:'TimeBasedTrigger'},action:{rotate:{overrides:{…rag re-key + deny-all isolation…}}}}` (or a `policyRef` to the `RAGSandbox` block), triggered by a `time-based-trigger` `SecurityEvent`, never a hidden timer; reuses the existing action union (no `MaxProperties=1` change).

#### D25g — Node-rotation API shape; is scheduled rotation in v1 scope

- **Paper basis:** [UNDERSPECIFIED → design decision]. Phoenix-for-AI p.4 (read) "moving the model to a clean, isolated node" specifies an event/panic trigger + the clean-node outcome only. Proactive §V.A "Staggered rotation" and §III.C.4 co-location motivate a scheduled/co-location cadence but pin no node interval, CRD shape, or restart-safety model.
- **Options:** (a) action-only `AMTDAction.NodeRotate` (panic-only v1, smallest, but no scheduled cadence and no object to reconcile an in-flight drain across restart); (b) action + `AMTDSpec.NodeRotationPolicy`, all status on `AMTDStatus` (both homed, reuses AMTD plumbing, but one object can't cleanly model N concurrent drains); (c) action + policy + standalone cluster-scoped `NodeRotation` CRD (restart-safe per-drain object; three coordinated surfaces, heaviest).
- **Decision (OUR choice):** **(c) ALL THREE, exactly as the locked kernel fixes:** `AMTDAction.NodeRotate *NodeRotateAction` (panic/event branch), `AMTDSpec.NodeRotationPolicy{Enabled,Interval,Jitter,MaxConcurrentNodes,Stagger,TargetNodeSelector}` (scheduled cadence tuning), and a standalone cluster-scoped `NodeRotation` CRD modelling an in-flight drain so progress survives operator restart. **Scheduled node rotation IS in v1 but is OPT-IN and DISABLED by default** (`NodeRotationPolicy` nil ⇒ panic-only), because node rotation is far costlier than pod rotation; panic-move is the always-available primary path. Per Rule #1, scheduled rotation is **not a hidden timer**: `NodeRotationPolicy` only **tunes** cadence; the rotation is still triggered by a `time-based-trigger`-emitted `{Type:'timed',Source:'TimeBasedTrigger'}` `SecurityEvent` matched to a `NodeRotate` action. The CRD reconcile is **class-(B) continuation only** and must not initiate a node-move the matcher did not first select.
- **Reasoning:** the kernel `D1` hybrid already reserves a standalone CRD for objects whose restart-safety/observability exceed a spec field, and an in-flight node drain is the canonical such object. Action+Policy+CRD satisfies all three paper-motivated modes (panic, scheduled/co-location, restart-safe drain) without a parallel trigger path. Defaulting scheduled OFF respects that no paper gives a node interval and that mass node rotation risks self-inflicted outage.
- **Downstream commitments:** registers `NodeRotation` at `cmd/main.go` L53/above L131; adds `NodeRotateAction`/`NodeRotationPolicy`/`NodeRotationStatus` to deepcopy/manifests; binds scheduled cadence to the single `time-based-trigger` owner; `Interval`/`Jitter` inherit the `D9` floor; populates `AMTDStatus.nodeRotations[]` (bounded).
- **CRD/SecurityEvent expression:** **realizes Rule #1** — panic = `{rule:{type:'panic',source:'KubeArmorIntegrator',match:[{field:'threatLevel',op:'In',value:'high,critical'}]},action:{nodeRotate:{strategy:'Cordon'}}}`; scheduled = `{Type:'timed',Source:'TimeBasedTrigger'}`→`nodeRotate`. The CRD reconcile and shadow-readiness are class-(B), not trigger paths.

#### D25g2 — Source-node disposition after relocating the pod

- **Paper basis:** [UNDERSPECIFIED → design decision]. Phoenix-for-AI p.4 (read) "moving the model to a clean, isolated node" says nothing about the **old** node. Proactive §III.C.1 motivates breaking the foothold but pins no cordon/taint/delete/cloud-termination choice. `Cordon;Taint;Delete` and "Cordon default" are flagged proposals.
- **Options:** Cordon (reversible, least disruptive, no cloud dep — doesn't evict the moved pod/co-tenants by itself); Taint NoSchedule/NoExecute (NoSchedule keeps co-tenants; NoExecute force-evicts everything = a mass-eviction lever); Delete Node + terminate cloud instance (most aggressive, needs cloud integration, irreversible, max DoS-lever).
- **Decision (OUR choice):** **keep the locked enum `NodeRotateAction.Strategy {Cordon;Taint;Delete}` with Cordon as the default** (flagged proposal). **Disposition semantics:** acts on the **source** node **after** the targeted inference pod is relocated and confirmed Running on a clean node. `Cordon` = mark source unschedulable (reversible; default; the replacement is pinned away so the pod cannot re-land). `Taint` = an AMTD-managed `NoSchedule` taint; **`NoExecute` is a SEPARATE, PDB-bypassing escalation rung** (kubelet-driven eviction that does **not** go through the Eviction API and does **not** honor PDBs), distinct from `D25g3`'s `DrainPolicy`/Eviction co-tenant drain — gated by `D26`. `Delete` = delete the Node object (+ optional cloud-instance termination) is the most aggressive rung, gated behind `D26` (trusted-`Source` allowlist + `ThreatLevel` floor + recommended human approval) and degrades to Cordon when cloud integration is absent. Relocate-first-then-dispose preserves the Service endpoint (§IV.D-5).
- **Reasoning:** Cordon-default is the minimum action satisfying "move to a clean node" (the moved pod, pinned elsewhere, can never re-land, breaking the §III.C.1 foothold for that workload) while being reversible and cloud-agnostic. Taint and Node-delete are escalating opt-ins behind the `D26` authz guard because a node-eviction primitive is a documented cluster-DoS lever. *(The kernel's "honors PDBs" property covers only the `DrainPolicy`/Eviction path, not `NoExecute`.)*
- **Downstream commitments:** `NodeRotationReconciler` implements the three dispositions via `nodes update;patch` (cordon/taint) and optional `nodes delete` + cloud hook (Delete); relocate-before-dispose ties to `InferenceReschedulePlanner.ExecuteWithServiceContinuity`; `Delete` wires the `D26` human-approval/allowlist gate; default Cordon keeps RBAC to `nodes get;list;watch;update;patch`; `Status` records the chosen disposition.
- **CRD/SecurityEvent expression:** disposition is a **field** of the `NodeRotate` action already in `Strategy[]` — it adds no trigger path; the `Delete` rung's `D26` gate keeps the DoS-lever behind the SecurityEvent provenance contract.

#### D25g3 — Co-tenant drain scope on the source node

- **Paper basis:** [UNDERSPECIFIED → design decision]. Phoenix-for-AI p.4 (read) speaks of moving "the model" (the targeted instance) — implies relocating the **targeted** workload, not draining co-tenants. Proactive §III.C.4 (co-location) motivates removing the shared-node surface but prescribes no drain scope or PDB handling. The kernel names Eviction-API-honoring-PDBs and a no-mass-eviction invariant.
- **Options:** relocate only the targeted pod + cordon (safe default, zero collateral, leaves the attacker other co-tenants); drain ALL pods via the `policy/v1` Eviction subresource (best co-location removal, cascades disruption); drain only other AMTD-managed pods (scoped middle ground); configurable via `DrainPolicy`.
- **Decision (OUR choice):** **DEFAULT = relocate only the TARGETED inference pod + cordon the source (NO co-tenant drain)** — the safe reading of "move the model." **Opt-in escalation** via the locked `NodeRotateAction.DrainPolicy *DrainPolicy{GracePeriodSeconds,IgnoreDaemonSets,DeleteEmptyDir,Force}`: when set, the reconciler drains co-tenants through the `policy/v1` **Eviction subresource** so PodDisruptionBudgets are honored (delete fallback only when configured). **Hard safety ceiling (locked no-mass-eviction):** regardless of `DrainPolicy`, drains obey `NodeRotationPolicy.MaxConcurrentNodes` + `Stagger`, so a full-drain config can never evict the whole fleet at once. DaemonSet pods skipped by default. "Drain only other AMTD-managed pods" is expressible by scoping eviction to the `AMTD_MANAGED_BY` label set.
- **Reasoning:** targeted-pod-only is the least-surprising, lowest-collateral reading of "move the model" and the only scope unconditionally safe under load; full co-tenant drain (best for §III.C.4) is gated behind an explicit `DrainPolicy` AND the `MaxConcurrentNodes`/`Stagger` ceiling. Using the Eviction API (not raw delete) respects PDBs and prevents breaking co-tenant quorum.
- **Downstream commitments:** `NodeDrainer` wraps `policy/v1` Eviction (RBAC `pods/eviction create`, `policy poddisruptionbudgets get;list;watch`) with delete fallback; `DrainPolicy` nil ⇒ skip co-tenant drain; `MaxConcurrentNodes`+`Stagger` enforced as the ceiling; `Status` records evicted co-tenant count.
- **CRD/SecurityEvent expression:** drain scope is a **field** (`DrainPolicy`) of the `NodeRotate` action — no new trigger path. The Eviction+PDB+`MaxConcurrentNodes` stack ensures the matcher-selected node action cannot become a mass-eviction backdoor.

#### D25g4 — What defines a 'clean, isolated node' + pinning + stateful destination

- **Paper basis:** [UNDERSPECIFIED → design decision]. Proactive §IV.B "ephemeral node assignments" and §V.D "rotating containers, nodes, and configurations … reducing dwell time to mere minutes" + Phoenix-for-AI "clean, isolated node" give NO node-selection algorithm, NO definition of "clean/isolated," NO storage/GPU relocation rule. `TargetNodeSelector` is load-bearing; NIM has **no inference selector** (`For(&corev1.Pod{})` L180 watches ALL pods); local-PV/topology-PVC/GPU-MIG and crash-mid-drain rollback are flagged hazards.
- **Options:** clean = admin pre-provisioned label pool (`r6security.com/clean-pool=true`), pinned via injected `nodeAffinity` on the **shadow/replacement** spec, target-set = explicit `InferenceSelector`, PVC/GPU pre-checked, `NodeRotation` CRD reconciles to completion (deterministic, admin-owned, GitOps-friendly, no cloud dep, restart-safe); clean = any untainted node with zero flagged pods, `spec.nodeName` pin (a race; `spec.nodeName` bypasses the scheduler so PVC/GPU/affinity/taints are NOT honored); clean = freshly autoscaled (Karpenter) or TPM-attested (strongest, heavy deps absent from repos).
- **Decision (OUR choice):** **(a).** v1 "clean node" = the `CleanNodeSelector` **label-pool** default: a node carrying `TargetNodeSelector` (proposed `r6security.com/clean-pool=true`), schedulable, and **excluding** the source node + any node hosting a currently-flagged pod (`excludeNodes`). **PINNING:** inject `nodeAffinity`/`nodeSelector` onto the **REPLACEMENT** pod spec (the warm-swap shadow per `D3`-primary, or a one-shot pinned recreate via cold fallback) — **never** patch a shared owner template (would rotate all replicas) and **never** `spec.nodeName` (bypasses scheduler → defeats PVC/GPU/taint admission). **PVC/GPU GUARD (precondition, not silent failure):** before relocating, `CleanNodeSelector` verifies the candidate satisfies the pod's volume topology (node-affined/local PVs ⇒ candidate must be the right node or the pod is unrelocatable) and has free GPUs of the required type/MIG profile; if none qualifies, **abort with `Status` `phase=NoCleanTarget`** (reason `CleanPoolExhausted|PVCTopologyBound|NoMatchingGPU`) rather than landing an unschedulable pod. **TARGET-SET:** close the ill-scoped set via `InferenceWorkloadPredicate` / an explicit `AMTDSpec.InferenceSelector` (label selector + optional image prefixes); a `NodeRotate` relocates exactly the in-selector inference pod(s) on the source node, NOT every pod NIM watches. **CRASH-MID-DRAIN:** the cluster-scoped `NodeRotation` CRD records `phase {Cordoning,Draining,Rescheduling,Pinning,Completed,RolledBack,NoCleanTarget}`; on restart the reconciler resumes from phase (class-B continuation); on unrecoverable failure it uncordons the source (Cordon is reversible, `D25g2`) and records `RolledBack`.
- **Reasoning:** the label-pool is the only option that is admin-auditable, has no external dependency, and lets "clean" be an explicit operator assertion the controller can act on deterministically; attested/autoscaled pools become pluggable `CleanNodeSelector` impls behind the **same** interface so v1 is shippable. Pinning the replacement spec (not `spec.nodeName`, not the owner template) is forced by two correctness facts: `spec.nodeName` skips scheduler admission (silently breaks PVC/GPU/taint), and patching a shared template has no per-pod identity (the `D3` ill-posedness). Making PVC/GPU a precondition that fails loudly (`NoCleanTarget`) honors the "explicit non-durability over false success" discipline. The `InferenceSelector` closes the verified L180 all-pods gap.
- **Downstream commitments:** pins `CleanNodeSelector` to the label-pool impl + the PVC-topology/GPU-MIG precheck; adds `AMTDSpec.InferenceSelector` (also NIM's scope fix); makes replacement-spec `nodeAffinity` injection the pinning mechanism; adds `NodeRotation` CRD phases incl. `NoCleanTarget`/`RolledBack` + resume-from-phase; RBAC `nodes get;list;watch` + `pods list`; ties warm relocation to cap#2 for Service continuity.
- **CRD/SecurityEvent expression:** **realizes Rule #1** — relocation is invoked only via the `NodeRotate` action selected from a `SecurityEvent`; the clean-node definition, pinning, PVC/GPU guard, and target-set are all **how** the selected action is realized (and where it honestly aborts); the CRD resume loop is class-B continuation, not a trigger.

#### D26 — Node-rotation trigger authentication/authorization (cluster-DoS lever)

- **Paper basis:** [UNDERSPECIFIED → design decision]. `NodeRotate` grants node-write + pod-eviction RBAC (verified NEW: **no** existing `nodes`/`eviction` kubebuilder:rbac anywhere in the operator); `SecurityEvent` is cluster-scoped (L52) and emitted via thin RBAC-gated REST POSTs, so an actor able to forge SecurityEvents could cordon/taint/delete **every** node → cluster DoS. The papers specify no trigger-authn model. `D26g` already establishes the SecurityEvent.Spec RBAC trust root for **scores**; `D26` is the same provenance principle applied to the highest-privilege **action**.

## Cross-cutting conflict resolutions

These are the cross-theme conflicts surfaced by the global LOCK, each with its locked resolution. They are binding and override any narrower reading above.

### C1 — Integrator threat-level/type vocabulary vs the conformance guards

**Conflict.** The conformance `NodeRotate`(`Type:'panic'`), `Regenerate`(`Type:'drift'`), `Quarantine`(`Type:'policy-violation'`) rows and `D26`'s authz gate key on `Rule.Type` and `ThreatLevel In {high,critical}`. Verified emitters do **not** produce those literal tokens: `falco-integrator` emits `Type=`rule-name, `ThreatLevel=`Priority (`'Critical'/'Warning'/…`), `Source='FalcoIntegrator'`; `kubearmor-integrator` emits `Type=`PolicyName, `ThreatLevel=`numeric Severity, `Source='KubeArmorIntegrator'`. So those rows are inert on raw integrator output, and "works with unextended integrators" is true only for the **score axis** (no numeric `AnomalyScore`), NOT for the `Type`/`ThreatLevel` string guards.

**Locked resolution.** Record a **per-integrator THREAT-LEVEL/TYPE NORMALIZATION prerequisite** as a first-class invariant (sibling to the score-carrier dependency and the Falco-Container-Drift→`Type:'drift'` mapping): (a) the `Source` guard IS emitter-native — keep it as the load-bearing half of `D26`'s allowlist; (b) the `ThreatLevel`-floor and `Type` guards require **either** an additive normalization in each integrator (map Falco Priority / KubeArmor Severity → canonical `{info,low,medium,high,critical}`, map the enabled Falco Container-Drift rule-name → `Type:'drift'`, runc/escape rules → `Type:'panic'`) **or** operator-authored guards in native vocabulary (e.g. `threatLevel In 'Critical,Warning'`, or a numeric `Gte` for KubeArmor Severity via `Rule.Match{Field:'threatLevel',Op:'Gte'}`). Additive (no new schema). Until normalization lands, a `Source`-guarded panic/drift row simply does not fire — **fail-safe**. Both the conformance matrix and the node-rotation text carry this prerequisite explicitly; "works with unextended integrators" is qualified to the score axis only.

### C2 — "Immediate panic" vs the min-interval floor and anti-flap hysteresis

**Conflict.** `D25` says a score ≥ `panicThreshold` "immediate panic mutation" **bypasses** the `D22`/`D9` min-interval floor, while `D22` requires N-consecutive-high hysteresis + readiness before any panic and NO-ROTATION-STORM forbids re-mutating before the prior replacement is Ready. A naive reading of "immediate" (the product page's literal word) could be taken to bypass **all** guards (single-sample spike → unbounded storm).

**Locked resolution.** Unify the wording, stated **identically in both the `D22` and `D25` sections**: **"immediate panic" = bypass ONLY the min-interval cadence FLOOR, NEVER the readiness gate and NEVER the N-consecutive-high + EWMA hysteresis.** The min-interval remains the floor no availability SLO (`D27`) may breach; panic only collapses the inter-rotation **wait**, not the safety confirmation. No mechanism change — a locked-wording reconciliation.

### C3 — One product word "panic", two declarative actions

**Conflict.** The corpus uses one word "panic" for "immediate panic mutation → move to a clean, isolated node," but `D25` scopes its panic to score-keyed in-place `Rotate` (gpu '0' + `RUNTIME_MODE=SECURE`) and routes the node-move to a **separate** `ThreatLevel`-keyed `NodeRotate` (cap#7). Risk: a reader expects one panic action to do both, or expects the node-move to be score-driven like the `Rotate` panic.

**Locked resolution.** "panic" is realized as **TWO distinct `MaxProperties=1` `Strategy[]` actions**, each selected independently by the matcher: (1) score-keyed `Rotate(panic)` `{Source guard + anomalyScore Gte panicThreshold}` for in-place GPU-quarantine/secure-degrade (rides `D22` hysteresis); (2) `ThreatLevel`/`Source`-keyed `NodeRotate` `{Source In allowlist + threatLevel In high,critical}` for the clean-node move (no numeric score required; works once `ThreatLevel` normalization (C1) lands; rides `D26`'s authz/DoS guard + Cordon-default). They **compose** (an operator may author both). Present "panic" as "one product word, two declarative actions" with a `D25` ↔ `D25g`/`D26` cross-reference so no row implies a single hidden panic path.

### C4 — GPU-scheduling collision: gang-scheduling vs distinct-UUID vs clean destination

**Conflict.** Three GPU constraints can collide on real hardware: `D17` `Reassign` demands the replacement bind a **distinct** GPU UUID; `D11` demands N warm shadows **all** gang-schedule on scarce GPU VRAM; `D25g4` demands the clean destination have free GPUs of the right type/MIG. On a GPU-constrained cluster these can be jointly unsatisfiable, and the warm-swap path (`D3` primary) is exactly where `D17` distinctness and `D11` gang-scheduling both apply.

**Locked resolution.** **(a) FAIL LOUD, never silently land an unschedulable/non-distinct pod:** `D17` `RequireDistinctBinding=false` (best-effort) is the default, degrading to `SingleGPUFallback` (Status condition) when >1 distinct GPU isn't schedulable; `D11` records "warm guarantee void" if N shadows can't gang-schedule; `D25g4` aborts with `phase=NoCleanTarget` (reason `NoMatchingGPU`) rather than relocating onto a GPU-less/wrong-MIG node — the "explicit non-durability over false success" discipline applied uniformly to the GPU axis. **(b) PRIORITY ladder when warm-swap is the path: gang-schedule the warm pool (availability, the headline) > UUID distinctness (a hardening nicety) > DropToZero quarantine** — if distinct-UUID and gang-schedulability conflict, keep the warm shadow Ready (serve) and record `GPUBindingDistinctness=BestEffortOnly`; do **not** refuse the swap. **(c)** `DropToZero` (the only verbatim behavior) is unaffected (needs no distinct GPU). The conformance matrix never claims warm+distinct+clean simultaneously on hardware that cannot provide all three.

### C5 — Image-verification fail mode vs self-heal-DoS guard vs availability SLO

**Conflict.** `D6` mandates admission **fail-CLOSED**; `D6g` defaults `OnDrift=Quarantine` (not auto-Regenerate) precisely because auto-replace is weaponizable into a restart-loop DoS, and bounds opt-in Regenerate by `D22`. But a transient registry/Rekor outage at admission (if fail-closed) plus an aggressive poll could mass-deny or mass-regenerate and breach the `D27` availability floor — the same self-DoS the guards exist to prevent.

**Locked resolution.** Endorse `D6`'s **split fail mode** explicitly: admission (synchronous, create/update) is **FAIL-CLOSED** (an unsigned image must never be admitted); the background poll / verify-before-recreate is **FAIL-TO-CACHED-LAST-GOOD-WITH-GRACE** (transient registry/Rekor unavailability surfaces `VerificationUnavailable` and reuses the last verified digest — **only a positive signature/digest MISMATCH counts as drift**). `OnDrift` default stays `Quarantine`+alert; opt-in `Regenerate` inherits the `D2` one-shot + `D22` min-interval/readiness/crash-loop-backoff guards **and** the `D24` `MaxConcurrentRotations` budget, so even a verification flap cannot storm. Net: **fail-closed only at the synchronous gate, never on the asynchronous poll**; every self-heal path is rate-bounded by the same `D22`/`D24` stack as rotation; the `D27` availability floor (`minInterval`) governs the self-heal path identically to rotation.
