## Selected question

Can an inference-only caller use one run-owned, unapproved, harmless zero-delta
LoRA route; can a separate observational detector identify its actual inventory
entry; does the installed Phorvex manager naturally choose and execute a native
response; and does the original model route then fail specifically while
ordinary base-model inference continues?

The observation mode is `OBSERVATIONAL_TEST_DETECTOR`. The separate observer
uses real inventory responses and an authenticated, allowlisted ServiceAccount.
It is a bounded test implementation of detection, not a hand-created alert and
not evidence that the installed legacy detectors work autonomously. Their 401,
event-contract and retired-state failures remain recorded.

Setup is performed by the test operator. The attacker has inference authority
only and cannot load, reload, modify or administer models. Zero-delta weights
are a harmless owned fixture, not malicious model weights. The security claim
is removal of unapproved model-route access, not model-answer poisoning.

## Permitted controlled changes

- Stage and load one uniquely named owned adapter per serial episode, using
  the existing reviewed offline zero-delta helper, exact Pod UID and owner file.
- Run one scoped observer process/Job with reviewed code, inference-only
  inventory access and the actual detector ServiceAccount identity.
- Create only run-owned temporary observer resources and its observed event.
  Preserve event UID, creator stamp, Pod UID and evidence before cleanup.
- Send bounded owned inference requests and retain complete noncredential
  response evidence, decision records and native journals.
- Clean up only exact owned resources and artifacts, after outcome and live
  retests. A needed final unload is labelled cleanup and cannot earn defense.

Current policy, scoring, enabled actions, safety constraints, serving deployment,
legacy detectors, authentication routes and unrelated workload data are outside
the permitted changes. The test driver must not directly create SecurityEvents
or invoke the native actuator to manufacture the observed response. The running
manager makes its ordinary choice. A missing capability or wrong choice remains
an observed failure and is routed through review before any expanded repair.

## Budgets and supervision

The final case freezes request counts, token limits, latency budgets, deadlines
and source/configuration pins before execution. The initial planning ceiling is
90 minutes, two serial fresh positive episodes (verifier and independent
reviewer), one active adapter of at most 8 MiB, and no new paid infrastructure.
Fixture preparation is not a fresh physical result. Negative oracle tests do
not earn live defense credit.

One supervisor grants the mutation lease for each episode. A changed target,
source, policy, endpoint, tool or adapter invalidates affected acceptance.
Stop on unexpected legitimate-service failure, unrelated mutation, source drift,
missing baseline, an unresolved native operation, or exhausted limits. Preserve
the first failure; do not tune criteria or erase journals to obtain a pass.

The public report will distinguish threat outcome, brain/effect attribution,
workflow completion and formal availability certification. Unknown action SLO
remains unknown even if sampled live continuity passes.
