# Prospective V3 follow-on: critical-path repair and clean control

Status: **PROPOSED; no execution authority**. 10 October 2026.

The first four physical episodes are complete and their outcomes remain
unchanged: three incomplete attempts and one independently checked
`LIVE_CASE_PASS`. The fourth proves one bounded deployed response. It does not
establish a successful independent reproduction pair or the required deployed
clean no-threat/no-signal control.

This proposal follows the owner's instruction to test and refine the agentic
architecture before implementing LangGraph. It proposes one final bounded
follow-on, subject to independent contract/source review and fresh execution
freezes. Peer agreement or this proposal cannot authorize an episode.

## Question and prospective changes

Can the same real observation → installed brain → native adapter removal →
specific denial and ordinary-service path be reproduced by two independent
executors after removing avoidable delay from critical behavioral measurements,
with a genuine clean control before the owned adapter is loaded?

1. Move immediate application probes and the complete precleanup hold ahead of
   expensive bulk audit/log retrieval. Retain actual drain of every already
   started legitimate request. Capture all provenance before the durable report
   and before cleanup. Do not retry a failed HTTP request or reinterpret it as
   model-specific denial.
2. Retain a bounded exception **class**, without request credentials, arbitrary
   exception messages or response-dependent invented causes. Transport failure
   still fails closed.
3. Add an actual clean control: the watched unapproved route is absent, the
   separate authenticated observer actively evaluates its real observation
   predicate without producing an event, ordinary base-model inference works,
   and original event/native/audit captures establish the declared scoped
   absence during a measured window. This is distinct from the existing delayed
   observation control, where the route is already present.

The clean control does not claim the entire stack is threat-free or that the
installed manager is globally idle. Its exact target, signal/action class,
current operations and concurrent unrelated activity must be retained. The
supervisor lease serializes this study's workers; it cannot prevent every
installed manager action. A native receipt or coincidence cannot prove the
cause of an unrelated transport failure.

## Required admission and stopping

The engineering authors prepare candidate tools and meaningful adverse tests.
The independent reviewer must inspect actual code and the exact clean-control
predicate, scope, transport schedule, complete audit intervals, budgets and
failure handling. Source acceptance is separate from this budget proposal.
Only then may the lead freeze actual bytes and grant a new serial lease.

Before each stimulus, the independent executor checks current original runtime,
clock and protected operation state. Historical journal absence or a previous
successful run is insufficient. Stale identities, impossible timing, ambiguous
native activity, an ordinary request failure, missing evidence, unsafe ownership
or exhausted limits stop the episode. Preserve its outcome and confirm safe
cleanup before any later attempt.

At most these two additional episodes may occur. A failure does not reset the
counter. Without two complete independently sealed final-profile positives and
the actual clean controls, the required acceptance remains unmet and the final
report must say so. Formal SLO, production readiness, GPU twin fidelity,
installed legacy detection, new-actuator synthesis and broad stack coverage
remain outside the supported claim even if this case passes.

## Clean-control authority and sampling limits

The native predicate is **no new scoped action**. It may be established by an
actual named journal404, or by independently pinned unchanged prior-completed
state with its UID/resourceVersion/raw receipt hash, prior episode identity,
current authority and original timestamps. A retained completed journal is not
absence. Original authenticated audit records covering the complete declared
window must contain no selected/actuated adapter-rotate for the frozen target.
Do not delete a journal to create this condition.

Current protected operation state also governs fixture naming. If a safely
completed prior operation requires reuse of the exact owned adapter name, declare
that constraint, use fresh episode/event/request identities and actually restage
the fixture after its verified absence. A conflicting fresh name cannot bypass
the operation's admission rules. Ambiguous or active state stops execution.

Canonical class/target event lists at both boundaries establish sampled absence;
they do not prove that no fleeting event existed anywhere between two lists.
Retain the active observer's actual inventory/predicate/no-intent records and
the complete authenticated brain audit interval. State these sampling limits
explicitly; do not convert them to a global continuous-detection guarantee.
