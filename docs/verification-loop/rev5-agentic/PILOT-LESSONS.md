# Pilot lessons and execution troubleshooting

Read this with START-HERE before starting a campaign in Codex, Cursor, Claude Code, or another harness. These are operational lessons from the 14 October 2026 one-case pilot. Apply the relevant remedy to the failing boundary and continue ready work. They add no approval stage and do not replace the boss Rev5 requirements or the current owner's scope.

## What the first live diagnostic established

A controlled workload reached Running on the owner-designated AWS dev cluster at 12:18:10 UTC. At 12:18:12 the deployed Phorvex operator logged a tick for the same owned policy: one pod, zero selected actions, one infeasible result. The policy reported that `rotate` lacked `create` permission on `pods/eviction` in the test namespace. Its other enabled actions reported missing workload context. An independent read-only authorization check at 12:34 UTC returned yes for the operator service account in `crm` and no in the test namespace after cleanup, consistent with the live denial. The runner's successful create permissions do not establish operator permissions.

Manual cleanup removed the fixture namespace; the API subsequently returned NotFound. The observed customer CRM deployment remained two ready replicas out of two. This was a preliminary workload and operator diagnostic, with no accepted defense, complete decision trace, scenario battery, challenge, or fresh independent repeat. A benign sleep workload alone does not establish every reviewed AML.T0074 predicate. Do not infer failed detection from an aggregate tick or count manual teardown as mitigation.

The owner explicitly designated AWS dev for this pilot because no separate twin exists. This is a campaign-specific Rev5 environment deviation. Future customer campaigns retain read-only customer inventory and an admitted isolated twin unless their owner explicitly supplies a different scope. No timer tick grants execution authority.

## Establish the execution path early

1. Resolve the current owner scope and actual inventory and experiment identities. Record amendments as structured, hashed references. Reuse valid existing sessions and credentials. A previous instruction or adapter restriction must not silently override newer owner scope.
2. Discover executable adapters, not just their interface names. Verify the smallest complete path: approved fixture, permitted target, running native UID, actual brain input and response, native probe, and owned cleanup. Bind commands and dependencies before repeating planning. Keep full gate admission distinct from a separately authorized preliminary diagnostic.
3. Check the runner and the Phorvex operator separately. Record the operator pod, service account, policy selector, namespace, ordinary action vocabulary, capability status, and effective permissions. Positive runner RBAC proves only runner RBAC.
4. Start only ready, budgeted tasks. Give each blocker one owner, the actual failing command or invariant, an exit condition, and the next concrete artifact. Run independent ready work while its owner resolves it. Do not require a successful post-defense receipt before allowing the probe that will measure success or failure.

## Blockers and remedies

| Boundary encountered | Remedy and closure evidence |
| --- | --- |
| Execution target was treated as requiring a missing separate twin after the owner designated AWS dev | Root binds an explicit campaign execution profile and the owner's amendment hash to the actual connection and cluster identity. Keep the separate-twin criterion recorded as unsatisfied. Do not deploy a local stack, invent a second identity, or block on superseded target assumptions. |
| Interface contracts and helper tests existed without an executable fixture to brain to probe path | Root assigns one narrow engineering delivery for the exact missing adapter, owned files, command, input/output contract and deadline. Close it with a real scoped call and native evidence; another abstraction or unit test is insufficient. Test both paths: closed admission must refuse, and a valid reviewed admission must reach the real adapter through a recording executor during local testing. A command that always refuses is a partial delivery. The positive test must invoke the same production entrypoint and flags: injecting a Clock or client into a helper does not prove that main supplies its real default clock, authenticated connection and cleanup path. Bind future execution to persisted owner scope, reviewed evidence and a finite lease; a timer-authority boolean is never permission. |
| The task forbade live calls during authoring, and the delivered runtime permanently rejected real SSH | Separate the author and local-test scope from the future admitted operation. Tests must not dial AWS, but the implementation must support the actual trusted transport after reviewed admission. Exercise the same command path with a recording test executable; verify that the real executable is supported. Missing or invalid admission must still prevent effects. Do not ship a successful stub path beside an unreachable native path. |
| Local tests accepted a fabricated kubectl UID-precondition flag | Verify command contracts against the installed CLI before testing a recording executor. This pilot's `kubectl delete --precondition=uid=... --dry-run=client` failed at argument parsing without contacting AWS. Use the actual Kubernetes DeleteOptions UID precondition through a supported client/API path, and prove that a replacement UID survives cleanup. Removing an invalid field selector does not make an invented replacement flag valid. |
| A critic accepted the local handoff while the campaign still had no executable native path | Scope acceptance to the milestone actually checked. A passing return schema, process-launch test or `ACCEPT_READY` for local files does not close execution readiness. The root must reconcile remaining native blockers and continue the next bounded task. Critic questions must test the admitted real transport, supported operation semantics and observation interval, rather than only whether expected strings occur in the code. Preserve the prior review without promoting it to physical or full-loop acceptance. |
| Offline compilation failed on a new module graph despite some cached Kubernetes modules | Record the exact Go command, selected transitive versions, go.mod and go.sum. A different cached version does not satisfy the selected graph, and a missing sum or disabled download is a local tooling boundary. Resolve pinned public dependencies in a separate build-support copy, retain checksum verification, then rerun the exact graph check and compile offline. Do not edit a prior delivery or infer compilation from download success. Public dependency preparation is distinct from cluster access; preserve the implementation task deadline and any missed budget. |
| Local wrapper rejected read-only identity and permission diagnostics | A wrapper guard error is an internal tool restriction, not a cluster or RBAC denial. Add a narrow read-only diagnostic exposing only endpoint, CA hash and required authorization results; preserve secrets and the original wrapper. Match the chosen connection to actual cluster identity. |
| Placeholder fixture image `planned.local` could not be a runnable delivery | Pin an accessible image digest appropriate for the observed node architecture and a reviewed benign fixture command. Capture the runtime image ID, readiness, native UID and time. Never copy customer application code to make the fixture run. |
| SSH or command output was parsed as JSON before checking the output format | Preserve stdout, stderr and exit code. Keep connection banners separate from the structured result and validate the expected shape before parsing. Prefer structured tools; use proper shell quoting for arguments, not JSON string encoding as shell escaping. Stop at the actual parse boundary and correct it once. |
| Runner could create the pod, while the operator reported denied eviction | Check the real operator service account and namespaced `pods/eviction` create permission, independently of the runner. Use `kubectl auth can-i create pods --subresource=eviction -n NAMESPACE --as=SERVICE_ACCOUNT`; the resource-string form gave a false negative in this pilot. Preserve the denial as capability evidence. Route a genuine Phorvex permission/configuration delivery through its reviewed scope; do not grant cluster-wide rights or repair the customer's application. |
| Library metadata called an actuator `evict`, but the frozen brain had no literal action with that name | A library `exists` label is not a deployed capability witness. Review the real action semantics, including Deployment or ReplicaSet rescheduling. `rotate` must not be silently aliased to `evict`; deleting one pod may not satisfy workload gone and owner not rescheduling. An evidenced actuator gap goes to specification, engineering PR and a new reviewed epoch. |
| Fixture pod and audit tick were mistaken for a verified attack or a full brain decision | Establish the reviewed attacker predicate and its control. Capture the actual signal/input, decision or rejection, full trace and action accounting. Keep detection, selection, dispatch, enforcement and durable end state separate. A missing decision trace is an observation gap, not proof that detection failed. |
| Local tests used a different policy from the deployed one | Pin the actual policy and capabilities. The observed CRM policy had lambda 0.4 and 11 enabled actions; that is not a two-action default or permission to enable every action. Account for all 24 canonical actions with their real enabled, disabled, unsupported or rejected status. Do not force a favorable selection. |
| A watch immediately drained, then its replacement waited but still returned UNKNOWN on a real clock | Classify against the actual start and stop of the covered interval. Taking a new clock value after the final sample can make every stream fail the stop-edge comparison. Test a clock that advances between those operations. A quiet pod does not emit periodic watch events: establish its initial state and continuous resourceVersion coverage, or measure the declared sampling cadence and gaps. Validate native positive and absence controls. A wait, frozen-clock test or snapshot does not establish coverage or durability. |
| Client authorization matched a CA hash but construction discarded the CA and credentials | Bind the actual CA bytes and private credential or exec provider to the client used by the operation. Check its target, bounded timeouts and real authenticated discovery through the trusted connection. A CA string comparison and a constructor that never dials cannot establish executable transport. Preserve credential references only in reports. |
| Local progress validation accepted blank identities or bypassed admission through initialization | Validate non-blank normalized identities, references and adapter bindings at init, every EXECUTE transition and relevant in-EXECUTE changes. Check actual hashed evidence, not a note saying approved. Preserve the open finding until independently reviewed corrective bytes close it. |
| Harness engineering used a role/payload outside the base schema | Use a separately reviewed explicit schema supplement or an updated versioned contract. Record which validator passed. An external engineering return passing its supplement is not a base-schema pass and is not an ACTUATOR_DESIGNER return. |
| Finished workers remained counted as active; some deliveries exceeded their deadlines | Reconcile genuine native task IDs and end markers, requested versus observed models, source hashes and elapsed budget. Reusing a session for a new scoped task needs a new typed task and budget; it is not a second worker or an extension of the expired task. Record overruns honestly. |
| Supervisor messages queued or replayed acknowledged pasted input | Send one focused instruction to the verified existing session and track its native receipt and resulting action. Preserve unknown or owner drafts. Do not assume an editor shortcut cleared a multiline draft; verify it. Do not send repeated unanswered requests or restart the lead to improve message delivery. |
| Root returned to an idle prompt while the one-case objective remained open | Reconcile active jobs and reservations, then continue the next ready bounded task. A worker completion notification, written status, wake test or watch-window expiry is not loop completion. Record a real external blocker with an exit condition if no ready work remains. |
| Smoke cleanup succeeded but the draft runner lacked crash-safe cleanup | Production admission needs finite command timeouts, cleanup in exception-safe paths, recorded resource UIDs and deletion preconditions, and a native absence check. Preserve execution and cleanup errors independently. A successful deletion command alone does not prove the resource or namespace is gone. |

These remedies concern the verification harness and Phorvex capabilities. Bugs in customer applications are case inputs, not repair work for the loop. Any separately authorized maintenance of our own dev services remains outside the competition and must not become its critical path.

## Record a blocker once and keep it actionable

Use the existing progress blocker structure. Include the stage, observed symptom, failing command or invariant, immutable raw evidence reference, first and latest observation times, current owner, scope, exit condition, next artifact, and status. Separate an observed cause from a hypothesis. A repeated blocker update must add new evidence or describe a changed boundary; status prose and heartbeats are not progress.

When a remedy changes a source, policy, fixture, adapter or scope pin, retain the old attempt and invalidate its dependent acceptance. Close the blocker only against new evidence and the required independent review. List every engineering PR and subsequent deployment/retest under the same case; a merged PR is not a defended verdict.

Report selected candidates, admitted executable cases, physical observations, accepted gates and completed loops separately. In this pilot there was one physical diagnostic and zero accepted full loops. Calculate progress from accepted milestones and show blocked obligations; do not infer a percentage or ETA from model activity or its context meter.
