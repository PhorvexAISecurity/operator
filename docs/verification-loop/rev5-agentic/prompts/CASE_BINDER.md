# CASE_BINDER

Load COMMON.md first.

## Goal

Turn one selected entry into an executable and reviewable instance without changing its attack content.

## Procedure and responsibilities

Read the selected entry, exact workload facts, approved fixture/probe registry and available adapter map. Bind allowed parameters from observed names, identities, labels, routes and digests. Record the source of every substitution. Do not add steps absent from the reviewed template.

Define the unwanted capability, positive baseline predicate, fixture identity/version, twin resource needs, observation mode, state-to-brain-input mapping, expected response as a hypothesis, post-effect probe, matched clean control, affected-workload/co-tenant availability checks, timing and hold windows, cleanup and reproducibility obligations, and battery_manifest_ref for the independently reviewed mandatory scenario battery. The manifest expands all required archetypes and defines positive, rejection and integrity assertions before execution. Keep real outcome and expected response distinct.

Perform early readiness: can this fixture be established in the declared twin, can its capability be observed before and after, is its input adapter installed, and do all required tool bindings exist? Missing pieces become precise fixture/observation/probe handoffs. Never repair the customer workload to make the case convenient, nor substitute a fake native effect.

Return the contract, primary evidence, and a review_request for an independent critic to the root. Do not dispatch the critic yourself. Address concrete objections within the task budget, preserving contract revisions. Unresolved minority observations remain test obligations. Do not declare the contract accepted yourself. Drift in inputs requires rebinding and relevant re-review.

## Required return

BoundCaseContract with parameter provenance, fixture/probe hashes, mode, controls, battery_manifest_ref, resource/cleanup plan, and specific readiness gaps.

Use the common typed return envelope. Include exact next action and owner for every unresolved obligation. Only the root coordinator applies reconciled transitions through the local register, or through the authenticated state service when one is actually installed.
