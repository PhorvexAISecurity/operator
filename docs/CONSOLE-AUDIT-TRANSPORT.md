# Console audit transport and identity split

With `phorvex.console.enabled=true`, manager and console use separate Deployments and ServiceAccounts. Only manager mounts the RWO decision-audit PVC and webhook certificate. The internal audit source Service selects the manager Pod; the dashboard Service selects the console Pod. The audit PVC admission guard remains manager-only. The console has no PVC mount, so its Pod cannot hold the audit claim on a node after manager relocation.

Provision independent Secrets before enabling the feature. `serverSecretName` and `clientSecretName` each contain `tls.crt`, `tls.key`, and `ca.crt`. The server certificate SAN must match `serverDNSName`; the client SAN must match `clientDNSName`. Never put a CA signing key in these Secrets. Keep these leaves and keys separate from the admission webhook identity. The source checks the client chain and exact SAN; the console checks the server chain and exact SAN. This transport also works when `admissionWebhook.enabled=false`.

For certificate rollover, first distribute trust bundles that include the old and new CA, wait for Secret projection, then replace each leaf/key and verify new TLS handshakes before removing the old CA. Each audit request opens a fresh authenticated connection and reloads projected files. An invalid Secret, source outage, or manager relocation makes audit-derived API reads unavailable until the source reconnects; the console does not silently use an image snapshot or local decision file.

An audit listener configuration or certificate error at manager startup is logged and leaves manager reconciliation running; console audit endpoints fail closed because the listener is absent. Correct the Secret/configuration and restart the manager Pod to start the listener. A later certificate projection error rejects new handshakes while the manager keeps reconciling. Slow audit readers have an independent four-reader limit and deadlines; they cannot occupy the brain tick loop.

The read-only source exposes a manifest and fixed `live`/numbered-backup segment IDs (including configured vCluster segments). The manifest pins inode generation, byte size, and a hash of the first min(size, 256) bytes. Every chunk validates this captured prefix; both source writes and client reads have a 10-second total deadline. Reads use at most 1 MiB chunks, four concurrent source readers, and a 1 MiB per-reader cache. Readers pin the manifest boundary for each request and verify retention before reporting complete history or derived data. Appends beyond that boundary are picked up by the next request or live poll. A final JSONL line without newline is excluded from bounded summaries. Rotation keeps its old inode readable under a retained backup. The supported audit writer contract is append plus rename rotation: detectable prefix reset, truncation below a pinned boundary, or evicted generation fails closed. An arbitrary in-place rewrite that restores the same inode, prefix and size is outside this contract and cannot be proven from the manifest alone. Raw history scans all retained segments with bounded pages and cursors, so users can page older decisions without downloading the whole audit. A new console Pod can serve after its first authenticated source read; it does not perform a multi-GB startup copy.

The console admits at most four short audit-derived requests before source probing or allocation and gives them a 30-second total request budget. Live SSE uses two separate subscription slots so long streams cannot starve history. Excess requests return 503 promptly. Health, session and capability endpoints stay reachable when the source is down or its read slots are full. A browser stream that misses multiple rotations between polls emits a visible gap notice and closes; the operator must use paged history to recover intervening retained decisions.

Owner summaries and the cost trend read at most the latest 16 MiB and retain at most 5,000 newest decoded decisions from live audit. Their responses include a `partial` flag and actual covered decision times; the UI labels those totals as a latest-window result when earlier bytes or decisions are excluded. Full-range estimates outside that coverage must be unavailable or explicitly marked partial. Paged raw history remains the route for older retained decisions. The live-clear control is disabled with an explanation in remote mode, and `/api/live/clear` returns explicit unsupported status: this read-only identity cannot truncate the manager file. Standalone local-file console behavior, including clear, remains available when no remote source URL is configured.

Rollout order: create and validate the two transport Secrets/CA/SANs, deploy the split manager and console, verify the internal audit Service has only manager endpoints and the dashboard Service only console endpoints, then check authenticated `/api/live/history` and live updates. `allowWorkloadMutations` opts the console ServiceAccount into Pod/Service mutations used by existing attack adapters; the manager retains only its reconciler permissions. Keep the source certificate operational and its endpoint reachable through manager rescheduling so console readers can reconnect.
