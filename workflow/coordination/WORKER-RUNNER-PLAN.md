# Lead plan: supervised Claude implementation workers

Owner: codex-lead. Implementer: claude-worker-runner. User authorized automatic Claude workers and a tier-by-tier reviewed PR campaign on 2026-09-10.

## Problem and intended behavior

Manual windows and unreliable native peer wakeups have delayed implementation. Add a small standard-library Python CLI runner using the installed Claude CLI in noninteractive print mode. Persist explicit session identity and a queue of bounded jobs. A new job for an existing worker resumes that exact session. Run the supervisor as a user service so shell exit does not discard results. Do not depend on Claude native socket writes to deliver assignments.

## Required implementation

1. Add `workflow/coordination/workers.py`, tests, and a concise WORKERS.md runbook. Runtime under the shared Git common directory, private to this user; keep logs, session IDs and prompts out of tracked files. Discover Claude via explicit --claude, PATH, then installed VS Code native binary with deterministic validated selection. Do not change global Claude/Codex permissions or auth.
2. CLI supports register (unique worker id, exact existing worktree, role, model, permission configuration), enqueue (idempotency key + prompt file), status (JSON), run supervisor, and stop/cancel owned jobs. One worker has at most one active invocation; global concurrency configurable, default 3. Job filenames/identifiers/path resolution must reject traversal and unintended repository/worktree targets. Registrations must share the same Git common directory; do not create/modify unrelated worktrees automatically.
3. Start `claude -p --output-format stream-json --verbose --session-id UUID` for first invocation, then `--resume UUID` for follow-ups. Use argv, not shell expansion. Use explicit session and invocation IDs; verify init/result session IDs and successful result.is_error=false, not only exit code. Capture actual model, tool denial, error, exit status, timestamps and final result. Worker turn completion means awaiting independent lead review, never task approval.
4. Durable atomic state + advisory locking. Idempotent enqueue must reject reuse with different prompt. Survive supervisor restart: no duplicate child for a still-live exact PID/starttime; interrupted/ambiguous jobs must be reported, not replayed silently. Consider subprocess output files and a per-invocation child wrapper so result receipts survive supervisor death. Crash windows before/after spawning and PID reuse need explicit handling. Stop must signal only owned verified process identity. Do not kill or attach to existing user-opened Claude sessions.
5. Every prompt carries assigned role/worktree/scope and standing rules: no co-author or AI attribution in any commit; preserve others' work; implementation author cannot approve its own code; no merge/deploy/live mutation; no new agents; report permission/error blockers honestly. Permission denial stays visible; never bypass to make progress. Support fixed scoped CLI tool allow/deny settings, no bypassPermissions, no arbitrary extra CLI flags exposing execution or session identity changes.
6. Optional bus completion notice to codex-lead using existing bus CLI, exact workflow_root and campaign/fix subject. Notification failure does not erase completed result; retry with durable receipt and no duplicate completion notice on ordinary restart. Do not claim exactly-once delivery across bus commit/crash without evidence. Lead can read authoritative runner results directly. Existing bridge and manually opened sessions remain untouched.
7. Unit/integration tests with a fake executable must cover first launch then same-session followup; two workers parallel vs same-worker serialization; duplicate enqueue; nonzero/is_error/missing-result/session mismatch; denials; process crash/recovery and no orphan duplicate; cancellation/PID reuse; worktree/path constraints; missing binary/auth failure; prompt/record privacy. Include instructions for a bounded real CLI smoke test (lead will perform).
8. Keep code modest and inspectable. Do not implement a self-approving tier scheduler. Tier readiness, source reconciliation, approval of fixes, PR review and live verification belong to the lead and existing workflow state. Document the user's stopping point: all current-tier PRs delivered, then wait for deployment and live verification before next-tier fixes.
