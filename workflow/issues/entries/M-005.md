### M-5 · Leader election off by default; tick loop not leader-gated · **HIGH** · ✅ FIXED (live-verified 2026-09-03, deployed `0.4.74`) · `CONTROL`
**What:** `--leader-elect` defaults false in binary and chart; `runner.Manager` implements no `LeaderElectionRunnable`. Two replicas both actuate.
**Live note (second pass, 2026-08-21):** this cluster's deployment runs `--leader-elect=true` with `replicas=1` — someone overrode the chart default here, so it is not biting *this* rig today. The default remains unsafe for anyone installing from the chart, and the tick loop is still not leader-gated in code.
**Fix:** default true in the chart; gate the runnable.
*Sources: A-9, A-155.*
**Eleventh-pass status (`v0.4.74` / `515c56a`, 2026-09-03):** **FIXED per this entry's own fix line by `1614a08` (PR #95, "leader-gate the tick loop"), deployed in 0.4.74** — the chart now defaults `leaderElection: true` (`charts/phorvex/values.yaml:41`) and the runner declares `NeedLeaderElection` (`internal/runner/manager.go:221`).
