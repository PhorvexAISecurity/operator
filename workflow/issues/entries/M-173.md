### M-173 · Primary running image projection selects a sidecar by status order · **HIGH** · NEW · `SENSE->CONTRACT`

**What:** The running-image producer chooses the first nonempty container status instead of matching the spec primary container by name. Live vllm records carry the sidecar digest; actual CollectSnapshot/Derive/EPSS and rarity consumers receive that wrong identity. Aligned ordering positive controls pass.

**Evidence:** intake/RPT-20260910-200300-primary-image-identity/VERIFICATION.md

**Required correction:** Match primary container identity across spec and status by name; preserve explicit absence when its running digest is unavailable. Verify reordered status, missing primary status, and aligned controls through actual consumers. Do not treat hypothetical EPSS fixtures as observed vulnerability severity.
