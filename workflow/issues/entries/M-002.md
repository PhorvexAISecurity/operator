### M-2 · CRD enum drift — the API server rejects four actuators TODAY · **MAJOR** · ✅ FIXED (live-verified 2026-09-03, deployed `0.4.74`) · `CONTRACT`
**What:** The kubebuilder marker on `ActionType` lists 12 enum values. At the audit commit (`880d2e4`) the committed CRD YAML still listed 17 (adding `adapter-rotate`, `request-drain`, `guardrail-rotate`, `kv-migrate-invalidate`, `disable`) — that was the drift. **At `v0.4.39` the drift is gone because the regression won: someone ran `make manifests` and committed the output, so the committed CRD now lists 12 too.** The five values are no longer "one regen away from disappearing" — they are gone from the repo, gone from the installed CRD, and rejected by the API server on any fresh install.
**Live evidence:** the installed CRD is at 12 values; server dry-run (2026-08-21) rejects policies carrying any of the five. `vllm/vllm-defense` (created 2026-08-11) still carries `adapter-rotate` via validation ratcheting (metadata/spec patches pass), but **the T14/T15/T22/T45 demo policy shapes cannot be re-created today** — including `adapter-rotate`, the actuator the flagship LoRA closed-loop demo rides on — and editing `vllm-defense`'s action list would permanently lose it until the CRD is fixed.
**Fix (order matters, and it flipped when the regression completed):** fix the MARKER first (add the five values to the kubebuilder enum), THEN regenerate and re-apply. A bare `make manifests` from the current marker re-commits the breakage.
**Implementation notes (verified at `v0.4.39` — both are the kind of thing that ships as a "fix" that doesn't fix):**
1. **The naive CI check is green on the broken state.** "Committed CRD matches `make manifests` output" passes TODAY — marker 12, CRD 12, they agree. That verifies self-consistency, and self-consistency is what the regen already achieved by deleting five actions. The invariant that actually bites is cross-package: **CRD enum == `model.MutatingActions` ∪ {`noop`, `disable`}** — the API vocabulary checked against the actuator vocabulary (`MutatingActions` is documented in `model/types.go` as the single source of truth). Write it as a Go test next to `completeness_test.go` — the existing completeness invariant proves every generatable action has a handler; this is its missing mirror on the policy side, and it should fail in the same place, for the same reason.
2. **The fix has two halves.** The API package's `ActionType` const block (`phorvexpolicy_types.go`) also has only 12 entries, ending at `ActionModelShardReplace`. Adding the five values to the marker but not the const block just moves the drift. Both need the five, and the cross-package test should assert against the const block too — or the next person adds one and not the other.
*Sources: A-194; regression-to-committed-CRD, const-block size, and `MutatingActions` vocabulary all confirmed at `v0.4.39` 2026-08-21.*
