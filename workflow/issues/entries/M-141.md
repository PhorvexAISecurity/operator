### M-141 · EPSS cache drifts stale against running digests — the highest-value entry silently matches nothing · **MEDIUM** · 🔴 LIVE · `SENSING`
**What:** The feed scores a pinned set of image digests; deployments move to new digests; the lookup is an exact string match with no repo-level fallback and no hit/miss metric. Entries silently stop matching the pods they were meant to score.
**Live evidence (sixth pass, 2026-08-23, `phorvex:0.4.43`):** of the 4 entries in the production cache, 2 match nothing running — including **litellm at EPSS 0.99999** (cache digest `afdc3cc…`, running digest `af80688…`), the single highest-value signal in the cache, which would nearly double that pod's asset weight in the objective. The vLLM entry matches and flows. A scrape of the brain's metrics endpoint shows no EPSS hit/miss series, so the miss is invisible to operators.
**Fix:** the feed resolves the cluster's *current* imageIDs (scan what's running; re-resolve on rollout) or the lookup falls back to repo-level latest-scan; export a hit/miss counter so a stale cache is a metric, not a surprise.
*Sources: sixth-pass live re-screen, 2026-08-23.*
