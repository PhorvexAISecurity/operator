### M-145 · Live policy editor rewrote `vllm-defense.spec.tenant` to `litellm` — M-140's name-keyed dual, reached through a console PATCH · **HIGH** · 🔴 LIVE (`v0.4.58`, 2026-08-27) · `SURFACE->CONTROL`
**What:** The live `PhorvexPolicy` `vllm/vllm-defense` currently carries `spec.tenant: litellm`. The brain therefore has **no vllm tenant**: `phorvex_ticks_total{tenant="vllm"}` is absent; decisions on `vllm/vllm-65b5489974-*` are stamped `tenant: "litellm"`; the 0.5 λ seed written on this object is installed on litellm's dual, not a vllm solver. `kubectl get` last-applied-configuration on the same object also shows `tenant: litellm` with a different action set — this is a console policy-edit (shipped `0.4.52+`, `internal/console/policy_edit.go`), not a delete/recreate.
**Why it is not just M-140 again:** M-140's proven vector was `Remove` failing to prune the bucket, so delete/recreate inherited state. This vector is a **write to the key itself**. Same stores (λ dual, RLS, belief prior, exposure clock), different operator gesture, and it was introduced by a feature in the `v0.4.50 → v0.4.58` window. Two workloads now share one economic unit because the UI allowed `spec.tenant` to be overwritten without checking uniqueness or "did you mean to merge these duals."
**Live co-observation (same scrape):** `phorvex_tenant_lambda{tenant="litellm"} = 0` against `selected=0`, `budget=5` — M-144 holds on the merged tenant.
**Fleet-wide (same build, 2026-08-27T18:15Z):** the tenant name is the unit independent policies collapse into. Live `PhorvexPolicy` list: **six** objects share `spec.tenant: voice` (5s tick) and **two** share `litellm` (vllm-defense + litellm-defense). Eight of nine policies fold into two duals; `phorvex_ticks_total` increments once per *policy* tick labelled by that name (`metrics.go:205`), which is why the voice series moves ~9× faster than nats. Not a scheduler bug — the same name-key as this issue.
**Fix:** policy-edit must not silently rewrite `spec.tenant` onto an in-use name (reject, or require an explicit merge); `costFor` / killchain memory / exposure clock should key by policy UID, not tenant string. Until then, any per-tenant claim about vllm at this build is a claim about a merged litellm+vllm dual.
