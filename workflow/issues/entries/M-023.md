### M-23 · Anti-over-rotation is mis-clocked for all pod-alive actions · **MAJOR** · 🔴 LIVE · `CLOCK->CHOICE`
**What:** `exposureVarFor` maps only kv-reset/kv-migrate-invalidate to the session clock; every other action falls back to the pod-identity clock — which pod-alive actions (quarantine, endpoint-rotate, adapter-rotate, request-drain, guardrail-rotate) cannot move. The epochs those handlers write feed nothing. In the steady state (long-lived pod), the cadence guard never engages for them: guardrail-rotate can flip variants and request-drain can re-drain **every tick** (the PHVX-67 pathology, six more times). Only adapter-rotate self-limits (it deletes its own trigger marker).
**Live evidence (second pass, 2026-08-21):** on a fresh tenant with a 90s `antiOverRotationWindow`, the brain emitted **8 rotate events in 90 seconds** across 3 pods (2–3 repeats per pod within 20s) before suppression engaged ~90s after each pod's first emission. So even for `rotate` (which IS clocked), the brake has a burst hole: the exposure clock updates lag the emission path, and on the Phoenix path nothing throttles between emission and clock update. The vllm tenant's kv-reset churn respects its ~110s cadence only because the native handler's effect lands fast enough for the clock to see it.
**Fix:** per-action exposure variables clocked from the epochs the handlers already write; wire them in `exposureVarFor` + the fingerprint map; record the rotation intent synchronously at emission time, not after execution.
**T1-B cross-reference (2026-09-04, cycle 3):** T1-B's clock origin/reset/owner table (`fixes/T1-B/03-decision.md`) names this boundary — the belief-side move clock is honestly renamed `SinceIdentityChangeSec` ("equals time-since-confirmed-move only for identity-changing moves"); the general per-action move-epoch clock stays here, `CLOCK->CHOICE`, not that ticket. **T1-B itself landed + L3-verified 2026-09-05 (`0.4.84` @ `4522076`)** — this entry remains OPEN (the per-action exposure-variable rewiring is its own future cycle).
