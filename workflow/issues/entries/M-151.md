### M-151 · `ModelRarity` is population-relative: dark on single-model fleets, saturated on two-model fleets — and the R-8 structural premise was inverted · **MEDIUM** · 🟠 STATIC · `SENSING`
**What:** `ModelRarity = rarity(modelFreq[p.ModelID], tot)` (`platform.go:163-164`) where `rarity(count,n) = 1 + log2(n/count)/log2(n)`, `n < 2 ⇒ 1.0` (`:192-198`), and `tot` counts only model-annotated pods. Consequences: (i) a sole model serving every model pod scores **1.0** — both AI GPU arms of `aiStageFromView` are dark on single-model fleets (measured live 2026-09-02: one distinct `phorvex.ai/model-id` fleet-wide ⇒ the R-8 misfire is currently *latent*, not live); (ii) with exactly two distinct ModelIDs every model is 1-of-2 and scores **2.0**, the maximum — the `> 1.3` / `> 1` conjuncts are near-vacuous wherever they can fire at all. The conjuncts gate on *fleet model diversity*, not on theft-relevant rarity. **Report erratum:** `VALIDATION_REPORT.md:1666` and bus 084 derived "one-model fleet ⇒ f = 1/N ⇒ ModelRarity = 2.0 ⇒ the > 1.3 test cannot fail" — the code computes the opposite (`rarity(N,N) = 1.0`, pinned by `TestRarityIsPopulationRelative`, `rarity_test.go:24`). The report's `BOUNDED > 1.3` remains valid *evidence* (the gate fired at `0.4.50`, so that fleet had ≥2 distinct ModelIDs); its structural claim is inverted and any R-8-derived reasoning citing it should be re-read against this entry.
**Fix:** decide what the conjunct should measure (per-node model scarcity? cross-tenant model adjacency?) and re-derive; until then treat both rarity-gated arms as fleet-diversity detectors.
*Sources: T1-A blind derivation (K3, `fixes/T1-A/02-critique.md` §A.2b); code + test at `016361c`; live ModelID census at `0.4.72`.*
