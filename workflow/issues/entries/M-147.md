### M-147 · `route-rotate` is priced as zero-disruption after the handler started changing Service selectors · **HIGH** · 🟠 STATIC · `ECONOMICS`
**What:** `internal/slo/bound.go:95` classifies `ActionRouteRotate` as `zero(...)` because "the shipped handler does not change Service selectors or EndpointSlices." That justification is false at `v0.4.64`. After R-3 the handler re-keys `phorvex.ai/route-key` and writes `svc.Spec.Selector[labelRouteKey]` (`handlers_k8s.go:363-365`). Two mechanical consequences: `selectionBound(route-rotate).Status == StatusZero` makes the runner record **`OutcomeCompleted`** (`manager.go:1093`), the strongest ledger outcome, for a selector re-key; `AvailabilityFor` (`bound.go:188`) returns `StatusZero`, "action has zero replica disruption." The handler's own comment concedes the pod re-key "can temporarily remove it from the old Service" (`:366`).
**Controls:** `identity-rotate` is the other `zero(...)` action in this set and its classification **holds** — it writes only `phorvex.ai/identity-epoch` (`handlers_k8s.go:286`). `endpoint-rotate` does the same class of Service selector update and is correctly `StatusUnknown` with `MaxUnavailableReplicas -1` (`bound.go:113`). This is not "the SLO model is optimistic"; it is one stale justification that was not updated when the mutation became real.
**Not M-33.** M-33 is the old coverless/label-only claim. R-3 made the restitch real; the SLO text did not follow.
**Fix:** reclassify `ActionRouteRotate` as `unknown` (same family as `endpoint-rotate`); stop granting `OutcomeCompleted` / zero replica disruption for a selector write.
*Sources: anatomy-v2 operation matrix 2026-08-31, `v0.4.64` / `fb52e6c`; `internal/slo/bound.go:95,113,188`; `internal/actuator/handlers_k8s.go:363-366`; `internal/runner/manager.go:1091-1094`.*
