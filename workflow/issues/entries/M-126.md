### M-126 · Tenant identity can overflow the 63-char label-value cap · **HIGH** · 🔴 LIVE · `CONTRACT`
**What:** `sanitize()` bounds at 200 chars; the result is written into label values capped at 63 — every EnsurePolicy Create rejected for long tenant names, suppressing actuation for that tenant every tick.
**Live proof (second pass, 2026-08-21):** clean A/B. Short tenant → AMTD `phorvex-pxv2short` created within seconds. 70-char tenant → every actuation attempt fails with `actuator EnsurePolicy failed; suppressing actuation this tick … metadata.labels: Invalid value: "pxverify-tenant-aaa…": must be no more than 63 bytes`, repeating every tick, and the AMTD never exists. Two graces: the failure IS ERROR-logged (not fully silent), and the CRD accepted the 70-char `spec.tenant` in the first place (no `maxLength` — itself part of M-3). But there is no metric and no status condition: a tenant whose name is too long is permanently disarmed, and only a log reader would know.
**Fix:** bound `spec.tenant` in the CRD (`maxLength: 63` or hash-suffix normalization in `sanitize`); surface EnsurePolicy failures in policy status + a failure metric (M-12).
*Sources: A-219; live A/B test V6 (2026-08-21).*
