### M-136 · The console's authentication is optional and fails OPEN — with mutation endpoints that shell out to kubectl · **CRITICAL** · 🔴 LIVE (third pass — and it is internet-facing) · `SURFACE`
**What:** The console (`internal/console/`, ~30 files) was never covered by any of the four audit axes. Its OIDC verifier is real (RS256, alg-confusion-resistant, fail-closed *given a verifier*) — but the verifier itself is optional. At `cmd/console/main.go` (~L71-82): if `PHORVEX_OIDC_ISSUER` is unset, `oidc = nil` and the console runs in self-described "demo-trust dev mode"; if OIDC is configured but **fails to load**, it logs `staying demo-trust` and continues — a misconfigured IdP silently disables authentication. In demo-trust, identity is whatever the request asserts: the lens gate (`scoped("operator", …)`) reads a self-declared `X-Phorvex-Lens` header / `?lens=` query param, and the vcluster paths read `?user=&tenant=`. Any HTTP client can name itself `operator`.
**Why it's critical:** the console ships mutation endpoints that shell out to kubectl — `/api/vllm/attack` and `/api/workload/attack` exec into pods, `kubectl patch phorvexpolicy`, and `kubectl apply` SecurityEvents (`vllm_attack.go` ~L37/67/90). The default path is documented as unsafe by the people who wrote it: `vcluster_endpoints.go:14` calls the fallback "demo-trust dev fallback (NOT for production)". The console runs as a container **in the operator pod**, so it holds the same SA token that M-4 grants cluster-wide `pods/exec`. ~~The chart defines no Service/Ingress for it~~ — **LIVE CORRECTION (third pass, 2026-08-21): the deployed cluster exposes the console via a `LoadBalancer` Service with a public AWS ELB hostname, port 80.** Live probes against the public endpoint: `/api/health` → 200 (reachability control); `/api/posture` with no lens header → 403 (the gate works as coded); `/api/posture` with a self-asserted `X-Phorvex-Lens: operator` header → **200 with full data**. No OIDC is configured on the deployment (no `PHORVEX_OIDC_ISSUER` env). So the exploit chain is no longer "anything already in the cluster" — it is **anyone on the internet → one self-asserted header → mutation endpoints shelling out to kubectl with an SA that can exec into anything.** (Mutation endpoints were NOT probed; the read-only 200 through the scoped gate is sufficient proof. One mitigant, verified: the `/api/apply-fix/*` applier is currently nil → record-only; the attack-demo endpoints are NOT record-only — they execute.)
**Note on root cause:** M-4 files the SA half ("the token is over-privileged"). This entry is the other half — the front door has no lock by default, and an unreadable key leaves it unlocked. Different fix; both are needed.
**Fix:** refuse to start the console's write paths when OIDC is absent or fails to load (fail-closed at boot, like the kill-switch); gate every mutating endpoint on verified identity; give the console its own SA with only the verbs the demo endpoints need (M-4); document the port as cluster-internal and add a NetworkPolicy default-deny (M-93).
**Live status (Round 1, 2026-08-25, `phorvex:0.4.50`):** ⬆ **severity escalation** — `GET /api/live` on the public ELB answers with **zero authentication** (no header at all → SSE connects), and with a self-asserted `X-Phorvex-Lens: investor` it **replays and tails the complete decision audit trail**: every tenant, every pod under defense, every action selected with cost/coverage internals, belief state (`stage`, `pHold`, hazards), R6 counterfactual narratives, and per-decision `objectsTouched`. That is a live, machine-readable map of the entire defense posture for anyone who asks. Found incidentally while closing C-1's evidence gap (the endpoint is the supported way to read `live.jsonl` remotely). Recommended: flag to the operator as **urgent**, not schedulable.
