### M-112 · EPSS: seeded once at boot, never refreshed; inert without a scan feed · **MINOR/ADVISORY** · ✅ FIXED at `v0.4.43` (live-verified) · `SENSING`
**What (as filed):** the exploitability cache was loaded once at startup and never re-read, and no pipeline produced the file — a feed writing into a void.
**Fix verified (sixth pass, 2026-08-23, on the running `0.4.43` build):** the new `epssfeed` package builds the cache from a Trivy scan plus the public FIRST corpus; a daily CronJob (`phorvex-phorvex-epss-feed`) runs it (completed runs observed); the brain re-reads the file every 30s (`--epss-cache-refresh=30s`, live in the deployment args) with a fail-safe reload that never clears a good cache on a bad read; and the ConfigMap now holds real digest-keyed scores (litellm 0.99999, nginx 0.528, vllm 0.0068). Startup log confirms: `epss: exploitability cache seeded {"images": 4}` + `cache refresh enabled {"interval": "30s"}`. The operational gap the fix exposed is **M-141**.
