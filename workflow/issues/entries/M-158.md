### M-158 · T1-E follow-up: boot DISCOVERY of the deployed CRD action enum into `model.NotInstallable` is unwired — the not-installable gate is live but its set is populated empty · **LOW** · 🔴 LIVE · `CONTRACT`
**What:** T1-E ships the full not-installable machinery — the gate's first (cheapest) check, `model.InstallSet`, pure `model.ComputeNotInstallable(AllKnownActions − installedEnum)`, the `not-installable` status emitter, and a constructed-set test — but the boot step that READS the deployed `phorvexpolicies` CRD enum and populates `model.NotInstallable` is deferred. The set is therefore always empty at runtime: on the current cluster (installed enum 17/17, re-verified 2026-09-05) that is behavior-identical, so shipping the gate was correct. The exposure: if the deployed CRD ever regresses to a shorter enum (e.g. a stale CRD after a partial upgrade), newly-undeclared actions are NOT excluded pre-scoring and the boot Warn does not fire — the gap T1-E's first gate was built to close stays silent until discovery lands.
**Fix (T1-E-followup, wiring layer):** at boot, read the installed CRD's `spec.…action` enum (apiextensions client), `model.NotInstallable = model.ComputeNotInstallable(discovered)`, boot-Warn per member. R3 already keeps `model` a leaf — the discovery lives in `cmd/` or the controller setup.
*Sources: T1-E cycle (claude bus 350 deferral, recorded in `fixes/T1-E/05-evidence.md` §scope; K3 P3 ruling D1 — accepted with this register entry as the tracker).*
