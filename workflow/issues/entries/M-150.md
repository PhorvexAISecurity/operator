### M-150 · `CoResidency` counts namespaces, and DaemonSets count as namespaces — the `> 1` conjunct is vacuous fleet-wide · **MEDIUM** · 🔴 LIVE · `SENSING`
**What:** `platform.go:115` builds `nodeTenants[p.Node][p.Namespace]` and `contributesToFleetPhysics` (`:84-86`) filters only on `Running` — so every system DaemonSet pod (kube-system, monitoring, CNI, …) registers its namespace as a "co-tenant". Measured live 2026-09-02: the vllm node carries 6 namespaces (`amazon-network-flow-monitor, gpu-telemetry, kube-system, litellm, monitoring, vllm`) → `CoResidency = 1 + clamp01(5/CoResidencyCap=4) = 2.0`, saturated. Any node running cluster daemons — every node — satisfies `CoResidency > 1`. The conjunct in `hazard.go:249/:253` therefore tests "this node has system daemons", not "an attacker can be co-resident"; and two actual tenants sharing one namespace would *not* count. The signal measures namespace topology, not co-tenancy threat.
**Fix:** count tenant identity (owner/tenant label), exclude system namespaces and DaemonSet-owned pods, or treat the conjunct as a config-gated hint with the vacuousness documented.
*Sources: T1-A blind derivation (K3, `fixes/T1-A/02-critique.md` §A.2a), live measurement at `0.4.72`; code at `016361c`.*
