### M-35 · `endpoint-rotate`: unconditional cover, conditional effect · **MAJOR** · 🟠 STATIC · `KNOWLEDGE`
**What:** The endpointPath credit is granted for every GPU/model pod, but the handler only stales a route when the pod carries a `route-service` annotation AND the Service Get succeeds (errors swallowed → relabel-only, still `Emitted:true`). The shipped console demo pre-plants the Service selector, so demo success doesn't prove the general path.
**Fix:** condition the grant on `RouteService != ""`; fail-closed on a declared-but-unreadable Service.
**Live status (Round 1, 2026-08-25, `phorvex:0.4.50`):** ✅ **CONFIRMED + SHARPENED** — the predicted swallowed-Get branch executed on production 246 times in ~70 min: the prod vllm pod carries `phorvex.ai/route-service: vllm-infer`, but no such Service exists; the handler silently relabels only (69 distinct route-keys in 69 min of pod sampling), booking full endpointPath cover each time with zero routing effect. The actual `vllm` Service selects on `role: leader`, which the re-key never touches. Sharpening: where the declared Service *does* exist, this same path is a non-atomic two-write route cutover every ~13s on a production serving workload (availability finding, higher severity). Evidence: `campaign/round-1/evidence/` (split-check + pods.ndjson drift).
*Sources: A-40, A-130; live confirmation Round 1.*
