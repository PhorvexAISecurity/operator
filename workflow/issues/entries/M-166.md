### M-166 · One pending console approval can be executed concurrently more than once · **HIGH** · NEW · `CONSOLE`

**What:** The real submit/gate/Approve HTTP path permits two concurrent approvers to enter the external Apply callback for the same pending request. Pending records are keyed only by caller-provided ID and can overwrite another tenant request; nil applier can still return applied. The shipped nil applier limits current cluster-write impact, but duplicate execution occurs with the supported real callback.

**Evidence:** intake/RPT-20260910-184000-approval-lifecycle/VERIFICATION.md; assessments/20260910-readiness/fresh-console/LEAD-REVIEW-R1.md

**Required correction:** Use a tenant- and generation-bound immutable request identity with atomic claim/terminal transitions, explicit apply attempt outcomes, idempotent retry and no applied response when an applier is unavailable. Authenticate approver separately under M136.
