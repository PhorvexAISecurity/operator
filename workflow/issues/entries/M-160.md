### M-160 · T1-E's no-rbac leg gates the two Phoenix-routed actions (rotate, quarantine) on the wrong principal's verbs — both are now candidacy-dead in every tenant except litellm/vllm, a live defense-coverage regression · **HIGH** · 🔴 LIVE · `ACTUATION`
**What:** The capability gate's verbs map (`actuator/verbs.go`) models each action's NATIVE handler mutations (rotate → `pods/delete`; quarantine → `networkpolicies/create`+`pods/update`), but production actuation is the hybrid actuator and `RuleTypeFor` (actuator.go:112) routes exactly rotate + quarantine to **Phoenix**, which enacts them via SecurityEvent/AMTD CR — the operator's SA only needs `amtd.r6security.com securityevents` write on that path (granted cluster-wide). The SA's native actuation power (`phorvex-actuation` ClusterRole) is bound by RoleBindings in **only litellm and vllm** (`actuatorNamespaces: []` chart default, unset in values-eks.yaml). So the SSAR honestly answers a question the production path never asks, and the gate excludes: measured live on `0.4.86` (T1-E L3) — rotate `no-rbac` in 10 namespaces (voice 684 rows, voice-prod 684, document-store 456, litellm-prod 456, nats 423, mcp/crm/crm-prod/ci-reports/vllm-prod 228 each), quarantine in 5, zero rotate/quarantine `selected` rows fleet-wide on 0.4.86 vs rotate selected on voice-prod in the 0.4.85 baseline window. `kv-reset` no-rbac on vllm-prod and `route-rotate` on litellm-prod are TRUE positives (native actions, binding genuinely absent — the gate working as designed). Net: the fleet's two headline defenses are candidacy-dead where Phoenix used to enact them — including voice (the e2e attack target: this is the decision-stream silence in yesterday's A05 failure, complementing M-155's Phoenix-race leg) and nats (the quarantine demo story). Invisible on the CRD condition (ActionsSupported covers capability, not RBAC — voice-prod reads `AllEnabledActionsSupported=True` while rotate is excluded there).
**Fix (CONTRACT, small):** make the RBAC leg routing-aware — for `RuleTypeFor(a) != ""`, gate on the verbs the Phoenix path needs from the operator SA (SecurityEvent/AMTD-CR write in the tenant ns), not the native handler's verbs; keep native verbs for native-routed actions. (OR-ing both verb sets is the conservative approximation.) Also consider feeding the no-rbac leg into the ActionsSupported condition so the over-exclusion is CRD-visible.
