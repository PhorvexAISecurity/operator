### M-152 · `stampGPU` drops `VRAMPresent` — the decision trace's VRAM field is permanently dark, even when DCGM data flows and the gate consumes the float · **MEDIUM** · 🟠 STATIC · `SENSING`
**What:** `internal/platform/adapters.go:19-29` (`stampGPU`) copies `GPUPresent`, `VRAMFraction`, `SMOccupancy`, `SMSource`, `LinkBandwidth`, `LinkSource` from the DCGM-populated witness — but never copies `VRAMPresent`, which `genericK8s.Derive` leaves false (`platform.go:183-184`). The only writer of the flag is `PopulateGPUWitness` (`prometheus.go:373`); the only reader is the decision trace (`coverage.go:673`, `traceOptional(v.Physics.VRAMPresent, …)`). Result: the trace shows `vramFraction {present:false, value:0}` on every record even when both FB_USED/FB_FREE answered and the stamped float is live — while the leakage gate (`hazard.go:246`) reads the raw float, so the gate can be armed by an input the record says does not exist. Verified live at `0.4.72` (2026-09-02): the brain's exact witness query `sum by (namespace, pod) (DCGM_FI_DEV_FB_USED)` returns `vllm/vllm-77997646c9-nhzv4 = 14488` from the very Prometheus the brain is configured to read, yet 1,193 consecutive vllm decision records all show `vramFraction present:false`. The trace therefore cannot distinguish "VRAM absent" from "VRAM live but flag dropped" — M-146's ambiguity class at the platform→trace seam, in the exact field R-9/T1-A need for gate auditability. SM presence is unaffected (keyed on `SMSource != ""`, which *is* copied).
**Fix:** one line — `w.VRAMPresent = gw.VRAMPresent` in `stampGPU`; add a presence-propagation test across the adapter seam.
*Sources: T1-A cycle live investigation (K3, `fixes/T1-A/evidence/live-baseline/06`), code at `016361c`.*
