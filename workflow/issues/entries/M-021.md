### M-21 · The default actuator rejects every AI-native move while reporting `ActionsSupported: True` · **MAJOR** · 🟠 STATIC · `CONTRACT`
**What:** `selectActuator` falls back to Phoenix on any unset/typo'd `PHORVEX_ACTUATOR` (no log, no validation); Phoenix errors on anything but rotate/quarantine; the support check never consults the actuator. A GPU fleet on the default actuator silently cannot enact AI moves.
**Live note (second pass, 2026-08-21):** Phoenix's execution of `rotate` is now live-confirmed (M-9). Its behavior on AI-specific event types remains unverified — and is currently untestable, because the M-2 CRD regression blocks creating policies that enable them. The two issues compound: the schema bug hides the actuator-coverage question.
**Fix:** `SupportsAction(action)` on the Actuator interface, consumed by the support check; log the resolved actuator on every branch; publish + test Phoenix's per-action repertoire.
*Sources: A-4, A-13.*
