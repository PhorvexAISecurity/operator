### M-3 · No admission control on `PhorvexPolicy` spec values · **CRITICAL** · ✅ FIXED (live-verified 2026-09-03, deployed `0.4.74`) · `CONTRACT`
**What:** Beyond the enum, the CRD schema places no bounds on the fields that drive actuation cadence and blast radius. Live-probed (second pass, 2026-08-21, server dry-run): negative `maxMovesPerTick`/`minAvailableReplicas` ARE rejected (≥0 bounds exist on those two), but `tickInterval: "0s"`, `antiOverRotationWindow: "-10s"`, and `proactiveFloor: "banana"` are all **accepted** — the duration fields are plain strings with no format check, so garbage only surfaces (if at all) as a runtime parse failure deep in the tick loop. `objective.lambda` is an unbounded string-encoded number (`"99999"` accepted).
**Fix:** CEL validation rules / bounds in the CRD (duration format + minimums, lambda range) + a validating webhook for cross-field invariants.
*Sources: R1; bounds mapped live 2026-08-21.*
**Eleventh-pass status (`v0.4.74` / `515c56a`, 2026-09-03):** **FIXED on main by `be0434c` (PR #97, "validate PhorvexPolicy admission", released v0.4.73), deployed in 0.4.74.** All four probe values this entry used (`0s`, `-10s`, `banana`, `lambda: 99999`) are now rejected: CEL rules + Pattern on the CRD (`api/v1alpha1/phorvexpolicy_types.go:165-166,200,207,215`) and a validating webhook (`internal/controller/phorvexpolicy_webhook.go:22-60`, `phorvexpolicy_validation.go`) wired by the chart (`charts/phorvex/templates/admission-webhook.yaml`, `values.yaml:45-46` enabled). Two caveats keep it 🔵: (i) the binary flag `--admission-webhook` defaults **false** (`cmd/main.go:128`) — the chart, not the binary, turns it on; (ii) the duration bounds live in the CRD under `charts/phorvex/crds/`, which `helm upgrade` never refreshes (same trap as M-2) — so live the CEL half may be absent while the webhook half is present. **Live check owed (K3):** dry-run the four probes against the cluster; confirm `ValidatingWebhookConfiguration` exists and the installed CRD carries the `x-kubernetes-validations` rules. Also note the new validator has **no rule for `maxMovesPerTick: 0`** — M-22's natural fix point, left open.
**Live verification (K3, 2026-09-03, deployed `0.4.74`):** all four probes rejected by server dry-run with precise field errors — `tickInterval: "0s"` → "must be a positive duration"; `proactiveFloor: "-10s"` → same; `objective.lambda: "99999"` → "must be between 0 and 10"; `mode: "banana"` → enum reject (`dryRun`/`active`). A complete valid baseline policy passes. The installed CRD carries 4 `x-kubernetes-validations` CEL rules (the `crds/` trap did NOT bite — the CRD was re-applied), and `ValidatingWebhookConfiguration/phorvex-phorvex-policy-validator` exists. Both halves live → CLOSED. Caveat (i) stands: the binary flag defaults false; a non-chart deployment is still unvalidated.
