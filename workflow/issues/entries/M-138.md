### M-138 · There is no recovery path: no bulk undo, no "revert last tick", no DR runbook · **HIGH** · 🟠 STATIC · `ACTUATION`
**What:** M-87 establishes that Rollback is never called outside the demo CLI. The operational consequence, unstated until now: if a bad policy quarantines 40 pods, the only undo is hand-parsing the `phorvex.ai/quarantine-snapshot` JSON annotation off each pod (`handlers_k8s.go:84`) and re-applying labels/ownerRefs with kubectl, one pod at a time. No runbook, no bulk-restore command, no documented DR procedure exists anywhere in the repo (the only "runbooks" are a benchmark guide and a test fixture). For a product whose entire function is mutating other people's workloads, the absence of a rehearsed undo is a gap no code-focused audit surfaces — it isn't a bug in any file.
**Fix:** a `phorvexctl restore <tenant|pod> [--since]` bulk-undo that consumes the snapshot annotations; a documented DR runbook; and wiring Rollback into the runner (M-87) so the path exists to be documented.
*Sources: third-party review feedback 2026-08-21; snapshot mechanism verified at `v0.4.39`.*
