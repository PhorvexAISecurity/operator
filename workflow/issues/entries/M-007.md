### M-7 · RBAC markers overgrant vs the committed Role · **HIGH** · ✅ FIXED (markers ⊆ committed Roles; installed chart-managed roles match templates — live-verified 2026-09-03, `0.4.74`) · `CONTRACT`
**What:** The kubebuilder markers request pods `patch`, endpointslices `update/patch`, and `serviceaccounts;secrets get/delete` — none of which any handler uses, and none in the committed Role. If anyone renders them, the blast radius silently widens.
**Fix:** trim markers to the handler-used verb set.
*Sources: A-174, A-85.*
**Eleventh-pass status (`v0.4.74` / `515c56a`, 2026-09-03):** **FIXED on main by `0d18fc8` (PR #94, "trim native actuator markers"), deployed in 0.4.74.** The unused `pods/patch` marker is gone (no `.Patch(` call exists in `internal/actuator`); the `endpointslices`/`secrets` markers were already removed pre-window (`ca50e82`). At `515c56a` the marker set (`internal/actuator/rbac.go:28-32`) is a subset of the committed Roles (`charts/phorvex/templates/rbac.yaml`, `config/rbac/phorvex-actuator-role.yaml`); `ephemeralcontainers` appears only in the opt-in Role B. B4-class entry (the finding is the code); the only live question is whether the installed Role equals the chart's — one `kubectl get role/clusterrole -o yaml` diff (K3) closes it.
**Live verification (K3, 2026-09-03, `0.4.74`):** the chart-managed roles match the templates exactly — `phorvex-phorvex-manager-role` (console-enabled branch: `securityevents` full verbs, `pods/log get`, `pods/exec create`), `phorvex-scanner-role`, `phorvex-feasibility-read`, `phorvex-console-reader`, `phorvex-leader-election`, `phorvex-phorvex-epss-feed`. The **actuation** path is not chart-managed at all: no `phorvex-actuator-routine` Role exists in any namespace; actuation runs on the hand-applied out-of-band ClusterRole `phorvex-actuation` — that drift is M-1's mechanism (fresh evidence appended there), not a marker defect. This entry's scope (markers ⊆ committed Roles) is closed.
