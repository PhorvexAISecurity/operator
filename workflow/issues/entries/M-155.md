### M-155 · The A05 e2e attack gate is a two-operator race: Phoenix's SecurityEvent controller can delete the redteam target before the brain's next tick — the attack DID react, just not in the decision stream, and the gate fails spuriously · **MEDIUM** · 🔴 LIVE · `ACTUATION`
**What:** the console's foothold (`POST /api/workload/attack`) is a `kubectl apply` of a `SecurityEvent` CR (`amtd.r6security.com/v1beta1`, rule `Panic`/`critical`) naming one target pod. That CRD belongs to **Phoenix**, whose `securityevent_controller.go` reconciles it event-driven and executes `Client.Delete(pod)` on the target — while the **brain** only sees the event on its next per-tenant tick (voice lands in a batch every ~10–20 s) and would then select+actuate rotate. Whoever wins the race decides what A05 observes. Live evidence (2026-09-05): PR #111 (21:39) and #112 (23:53) — brain's tick landed ~9 s after the apply, stage→`exploit`, threat 0.99, rotate actuated, A05 PASS. PR #113 (00:36, run `20260905T003628Z`) — Phoenix's reconcile was faster: the target (`voice-bot-…-nbbgx`) was deleted and replaced (`…-tl4hp`) inside the ~15 s gap before the brain's next voice tick; the event then pointed at a dead pod, the brain *correctly* did nothing, and A05 failed ("0 threat>0, 0 selected, 0 actuated") even though the attack demonstrably produced a reaction — just not one the check counts. Aggravator: once Phoenix opens a graceful delete, the brain's ingest drops the Terminating pod, so the brain's reaction window is Phoenix's reconcile latency, not the pod's lifetime. Note the PR-gate e2e exercises the DEPLOYED build, never the PR's code — this failure is unattributable to any PR by construction.
**Fix (harness/demo wiring, pick one):** (a) fire an event shape Phoenix's AMTD action table does not match (different rule type/source), so only the brain reacts; (b) teach A05 cluster ground truth — "the target pod was deleted in the window" IS a reaction, whoever performed it (the run's own `groundTruth` was empty); (c) opt redteam events out of Phoenix via a label/annotation its matcher skips. Until then: treat an A05-only failure with zero actuation and a vanished target pod as a known-flaky rerun, not a regression.
*Sources: PR #113 e2e run JSON vs #112/#111 (artifact `e2e-pr-113`, `run-20260905T003628Z.json`); `phorvex/internal/console/workload_attack.go`; `build/phoenix-extended/internal/controller/securityevent_controller.go` (Delete path L259, name-keyed dedup L200-212). Sibling of M-134 (adoption race) — same seam, opposite timing: M-134 loses events fired too early, M-155 loses reactions observed too late.*
