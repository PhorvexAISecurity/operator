1 · Executive summary

Phorvex is a deterministic AMTD brain: each tick it scores every candidate defensive move by consequence-weighted recon-facts-invalidated per dollar (Σ w(facts covered) − λ·cost) over a dynamically generated feasible action set, and selects the best move per asset under a per-tick budget. It is the intelligence layer; the Phoenix operator is the hands.

On live workloads this engagement showed:

  • Phorvex picks the context-appropriate actuator per attack — rotate for a stateless foothold, quarantine for a stateful one (preserving data), adapter-rotate for a poisoned LoRA, kv-reset for a cache-timing oracle.
  • With the new reactiveOnly mode, armed workloads stay calm (no proactive churn) until attacked — each response is a clean, attributable reaction.
  • Phorvex targets by value and cost, and preserves state + evidence — the explicit contrast against a blind fixed-timer defender (“R6”) that deletes pods on a schedule regardless of value or data loss.

4 · How Phorvex decides (the reasoning model)

  1. Recon-coverage objective. Each move invalidates recon facts (pod-identity, in-memory, session, network identity, lateral edges, adapter-integrity…), each weighted = assetValue · P(hold) · (0.5 + 0.5·stageUrgency). The move's score is per-dollar: coverage / cost.
  2. Shadow price λ. A per-tenant dual-descent solver maintains λ (the budget shadow-price). A move is “due now” only when per-$ > λ. A low-value move (per-$ ≤ λ) is noop'd — this is why Phorvex doesn't churn.
  3. reactiveOnly (new). An armed asset is actionable only when an attack signal targets it (a non-Phorvex SecurityEvent, a compromised neighbor, or an AI poison marker). No attack → calm/noop; attack → stage advances, weights jump, the right actuator fires.
  4. Feasibility laws (hard, pre-optimization): statefulIntegrity (vetoes rotate on stateful → quarantine), availabilityFloor (protects minAvailableReplicas), anti-over-rotation (evidence-retention window), conformal SLO gate (drops SLO-unsafe moves).
  5. Per-decision provenance. Every decision records perDollar, coveredFacts, stage→nextStage, pHold, λ, a SHAP-style attribution, and an R6 counterfactual (r6Would + r6Note).
