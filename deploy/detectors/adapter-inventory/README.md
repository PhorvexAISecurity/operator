# Adapter inventory producer: source proposal

This is an unapplied, single-incident producer proposal for an **owned vLLM fixture**. It repairs the installed detector's missing `phorvex.ai/adapter-name` and `phorvex.ai/target-pod-uid` annotations and noncanonical rule type without relaxing the manager's event trust, freshness, or exact Pod UID checks. The original contract failure and signed scope are recorded in [M187 evidence](../../../workflow/fixes/CAT-ADAPTER-DETECTOR/05-evidence.md) and [decision](../../../workflow/fixes/CAT-ADAPTER-DETECTOR/03-decision.md). No source test here proves installed detection, dispatch, adapter absence, benign availability, or security efficacy.

`detector.py` takes one exact namespace, Service, engine container, models port, explicit expected-adapter set, detector instance, and ServiceAccount identity. Each poll rebuilds one Ready Pod/EndpointSlice/Service UID join, checks the manager's effective Pod models port/path annotations, reads one bounded PodIP `/v1/models` response, and checks the join again. It accepts path-shaped and multiple base model IDs, requires coherent adapter parents and at most one unexpected bindable adapter name. Its direct models GET is an inventory observation only. HTTP is plaintext and appropriate only where a fresh read-only manager mode receipt shows `legacy-plaintext`; `secure-required` needs a separately reviewed authenticated transport. The current code cannot attest manager mode drift by itself, so this source must not be deployed as an unattended general detector.

Every HTTP call uses a 10-second absolute process timer, a 2-second socket timeout, and an 8-second monotonic body deadline with bounded `read1` chunks; redirects and application retries are refused. The longest successful incident-creation poll makes 16 serialized HTTP calls, so its HTTP stage has a 160-second configured ceiling, before local work and the next 15-second poll interval. A deadline during ConfigMap update or event POST is an uncertain mutation and never leads to a second POST in that process. Linux main-thread signal timers are a runtime prerequisite.

Before its only event POST, the producer pins the UID of an **operator-precreated empty ConfigMap** and claims it through resourceVersion CAS. The CLAIMED state records the exact Pod UID, adapter, deterministic attempt digest, and event name. After one exact event POST/readback, a second CAS binds the API-assigned event UID and makes the lock immutable (BOUND). The detector can get/update only that exact lock; it cannot create, delete, or patch it. Missing/recreated/foreign locks fail. Any ambiguous CAS stops that process; a restarted CLAIMED state refuses to adopt or create an event. BOUND requires the exact event UID, so a same-name replacement cannot rearm. If the bound event exists, it is retained even when inventory clears; changed Pod/adapter, expiry, or other conflict require terminal review. There is no auto deletion, renewal, or rearm. The [signed M187 decision](../../../workflow/fixes/CAT-ADAPTER-DETECTOR/03-decision.md) owns this narrow lifetime. A human or future coordinator must verify the manager's protected operation journal terminal phase and independent serving result before any separately authorized rearm. Simply deleting this lock would erase the single-shot guarantee; the pinned UID prevents this instance from treating a replacement as fresh.

`Dockerfile` uses the reviewed Python base digest, copies only `detector.py`, and adds no package/download dependency. `deployment.example.yaml` is **not apply-ready**: namespace and fixture, built image digest containing this exact source, precreated lock UID, manager serving mode/route, detector creator allowlist and admission stamp, policy/actuation grant, source mapping, and cleanup/terminal coordinator must each be admitted. Its fixed example namespace `adapter-catalogue`, instance `owned-proof`, and lock name `adapter-inv-lock-fd1adaf9bcd2e1e816fc0d37` are paired; changing either requires recomputing the name with `lock_name`. Record the precreated lock's API UID in `LOCK_UID` before starting the detector. The Role grants only the fixed ConfigMap's get/update; its SecurityEvent ClusterRole necessarily has cluster-scoped get/list/create because the CRD is cluster-scoped. Kubernetes RBAC cannot restrict those list/create verbs by target labels or path. No Pod patch/exec/proxy, Secret, event delete, or protected journal read is granted. The existing live Deployment/ConfigMap source owner remains unresolved; do not apply this example over the installed objects.

```sh
# from repository root
python3 -m unittest discover -s deploy/detectors/adapter-inventory -p test_detector.py -v
cd phorvex
go test ./internal/ingest -run '^TestAdapterInventoryProducerBindsOnlyAuthenticatedExactPod$' -count=1 -v
```

The Python suite uses fake API/model transports and verifies the saved `producer_envelope.json` is emitted by the current `run_once`, including both lock transitions. The Go test reads that tracked fixture through the unmodified `collectEventsAndReceipts` and `bindAdapterObservation`; it rejects wrong UID, absent authenticated creator, wrong rule, and stale API time. This package remains only a source proposal until its exact image, fixture, trust, mode, and ownership have separate rollout approval.

The existing unfiltered `pr-validation.yml` charts job runs the Python suite; the existing Go unit job runs the ingest fixture test. No CI job deploys this example or builds its image.
