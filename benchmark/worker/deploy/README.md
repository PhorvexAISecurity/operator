# Stage benchmark services

Install these user-service examples only from a reviewed release, replacing `REVIEWED_SOURCE`. They use the existing runtime Python, AWS/Kubernetes access and operator-provisioned exact-repository Git credential helper. No credential belongs in a request, unit or status artifact. The helper may fetch source objects; the installed credential's actual permissions are not narrowed by this command. Docker is unnecessary: replay is extracted from verified ECR image layers.

```sh
PYTHONPATH=benchmark/worker:. python benchmark/worker/stage_reconcile.py \
  --data /home/hami/phorvex-benchmark/stage-data \
  --repo /home/hami/phorvex-benchmark/operator-refactored \
  --ticks 64 --timeout 900 --max-work-bytes 268435456 --max-corpus-bytes 2147483648
```

The allowlist is fixed to `phorvex-staging-demo/demo-api-defense` and `phorvex-staging-demo/stage-bench-defense` in the explicit stage cluster. Repeated `--policy` may select a subset. This does not grant uploaded files authority to change scope or configure capture. Missing PVC/capture/readonly Console access is reported as BLOCKED with recovery instructions. Every cluster command is observational.

Reconciliation bootstraps from a recent inventory horizon (`--recent-seconds`, default 3600, bounded to 60..86400 seconds). This is an operational snapshot-discovery setting; it never changes a request's W/L or establishes endpoint coverage. The bounded metadata scan reaches a frozen upper timestamp before downloading its newest matching tail. If pagination is incomplete, it downloads nothing and retains source/policy/workload-scoped progress under `mathlab/reconcile-inventory` across cold retries. The newest exact requested cohort must still pass count, finalized-header, freshness and baseline checks. Sparse captures remain insufficient; old/frozen caches and historical reports are retained. Ordinary manual/request sync keeps its existing incremental semantics.

A source change is prepared under an exclusive global lease; real bot jobs retain shared leases. Exact image digest, embedded SHA, manager identity, policy/workload UID and generation are rechecked before publication. The exact source is fetched without changing repository HEAD. Native replay must reproduce every selected baseline tick from finalized producer snapshots. Immutable native receipts/cohorts live under `mathlab/native-baselines`; their exact hashes and replay identity are embedded in a single atomically replaced `mathlab/stage.json`. Old pins are retained in `mathlab/pin-history`. Native equivalence is not an independent cross-source review. Installing a reviewed experimental engine remains a separate explicit operation.

Source acquisition materializes the complete deployed-commit tree and current checkout HEAD tree required by the existing shared-clone build path. Merely having a commit object is insufficient. Explicit hydration stays within the source-growth/decoded-tree bounds; read-only readiness subsequently verifies the trees offline with lazy fetch and network transports disabled. Repository HEAD/configuration are preserved.

`mathlab/reconcile-status.json` is current operational status, not proof of endpoint history. Exit 2 is a structured prerequisite block and the timer retries. Readiness observation itself performs no downloads, pinning or Git lazy fetch. The service never changes policy mode or cluster configuration.

The observer supervisor watches only the isolated dryRun `stage-bench-defense` fixture. It stops only its own child on a verified scope change/unavailable observation, preserves prior journals and starts a new source/image/UID/generation-bound journal under `observer/managed`. It never issues a calibration or adopts active-demo history. `mathlab/observer-current.json` identifies the current journal. The refresh example resolves that pointer and verifies its source against the current pin. A new scope starts with no prior continuity, samples or attributed moves. Missing samples or requested W/L remain BLOCKED; quiet observation alone does not manufacture cost evidence.

Capacity is bounded separately from coverage: the default total working snapshot cache cap is 2 GiB across policies; temporary reconciliation work is 256 MiB; retained image binaries are capped at 512 MiB and native baseline evidence at 256 MiB. Only ownership-registered same-source working snapshots are pruned under consumer leases. Frozen runs/reports, baseline cohorts, pins and journals are retained. Reconciliation checks a 4 GiB filesystem free reserve before work/publication; source fetch has a 512 MiB growth guard. The compressed journal's 4 GiB encoded cap also enforces its existing free reserve; decoded size and scan time remain independent limits. Multiple retained source histories can exhaust these bounds and require an explicit operator archival decision. These settings do not prove ten-day capacity or continuity. Original ten-day requests are preserved and refused until their relevant actual evidence exists.

The normal journal scan default is 120 seconds (configurable up to 1800); refresh has its own 900-second default/1800-second maximum. Full long-window scans and total retained history must be measured before extending settings. A service restart/watch gap resets continuity honestly, and timer success does not imply ten-day readiness.
