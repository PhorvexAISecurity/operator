RLS is a fixed prior in production today

ObserveRotation exists and updates both RLS and conformal state, but repository search finds calls only in tests. The production operator loop has no caller. The headers in p1cost.go and rls.go now say “fixed prior,” so the current behavior is documented honestly rather than described as self-calibrating.

Missing and malformed telemetry scope

Absent connection telemetry is exactly neutral for the load term. Prometheus ingestion drops NaN and ±Inf samples before they reach the model (prometheus.go:193–200, 238–240), and the saturation helpers also neutralize NaN. Direct +Inf input saturates to full load rather than neutral, but the production ingestion boundary filters it. A future RLS wiring must likewise reject non-finite measuredFlow; ObserveRotation does not currently validate it.

1.2 is a gate threshold, not the mathematical maximum cost

Because rotate’s C_flow is clamped at 2, default-weight ECost can reach 0.4 + 0.6×2 = 1.6. Conformal slack can make CHi larger still. The 1.2 value is the policy’s exclusion threshold: candidates above it are removed; it is not a universal upper bound on values the model can compute.

The “always finite and non-negative” invariant needs an input contract

Empty or syntactically invalid policy fields fall back to 0.4/0.6, but strconv.ParseFloat accepts strings such as "NaN", "+Inf", and negative numbers. The CRD fields are strings with no numeric range pattern, and ECost has no final finite/non-negative guard. The invariant is proven for valid, finite, non-negative policy weights and finite model state—not for arbitrary policy input.

SecurityPerCostDollars is not a dollar-valued output

The formula is dollar benefit divided by dollar cost, so the result is a benefit-cost multiple ($ avoided per $ spent), dimensionally $/$ and normally treated as a ratio. Reports nevertheless label it SecPerCost($) and prefix it with $ (internal/report/dollars.go:237, 246–250; cmd/p3report/main.go:505–523). The arithmetic passes; the unit assertion and UI label fail.

“Annual” and horizon semantics are only coherent at the default h = 1

The runner passes a per-trial defensive-action count directly into the annual-cost formula; there is no attacks/year or trials/year rate. At horizons other than one year, GPU overhead multiplies by h despite its “PerYear” name, while the defense floor is not multiplied by h and only the action term is. The requested default numbers remain correct because h = 1 hides these inconsistencies.

Dollar constants are not all in one place

The five configurable defaults and their units are documented together in internal/config/config.go. Fixed constants—8760 hours/year, 1/60 GPU-hour/action, and the $1/GPU-year floor—live in economics.go. The console also has an independent cost model with a measured perActionSeconds, built-in AWS prices, and an R6 churn factor. The “one place” requirement is therefore only partially met.

Findings

Prioritized remediation register

F-01 · HIGH

Unitless optimizer ratio is dollar-labelled

OPEN
Evidence
Decision.PerDollar, phorvex_pod_per_dollar, “cov/$cost,” and “per-$” all divide coverage weight by dimensionless ECost.
Impact
Violates the “never share an axis” requirement at the operator/audit presentation layer and can make a unitless optimizer score look like money.
Recommendation
Rename to PerCostUnit or CoverageEfficiency; migrate the Prometheus metric with a compatibility window; remove $ from reason strings and UI.
F-02 · HIGH

“REAL AWS $/yr” has no expected-loss model

OPEN
Evidence
Console formulas multiply annual infrastructure rental cost by disruption/prevention; no breach frequency, P(active), or loss impact is present. Prices are local table values, not an AWS pricing API response.
Impact
The output is an infrastructure exposure proxy, not actuarial expected loss, and “live AWS price” overstates price provenance.
Recommendation
Add an explicit sourced expected-loss term or relabel as an “AWS infrastructure exposure index ($/yr-equivalent).”
F-03 · HIGH

Non-finite and negative inputs are not comprehensively rejected

OPEN
Evidence
Policy decimal strings allow NaN/Inf/negative parsed values; ROI validation checks authorization and trial basics but not ROI ranges; calibration accepts any measured flow.
Impact
The requested finite/non-negative invariant is not global. Malformed configuration or a future bad calibration sample can poison ranking or reporting; a NaN CHi also fails the gate open because NaN > ceiling is false.
Recommendation
Validate finite non-negative policy weights and ROI inputs at ingestion, validate action counts, and reject non-finite calibration observations. Keep final defensive guards in math functions.
F-04 · MEDIUM

SecurityPerCost and annualization units are misleading

OPEN
Evidence
SecurityPerCostDollars is $/$; per-trial actions are treated as annual/horizon actions; horizon scaling is inconsistent for h≠1.
Recommendation
Rename the ratio to BenefitCostRatio; introduce an explicit action-rate/year; decide whether functions return annual rates or horizon totals and apply horizon consistently.
F-05 · MEDIUM

Dollar constants are split across multiple models

OPEN
Evidence
ROI defaults live in harness config; fixed conversion constants live in economics; console pricing/churn uses a separate set of constants.
Recommendation
Define named, unit-bearing parameters per model and document which model powers each screen. Avoid implying the harness and console are one dollar formula when they are not.
F-06 · INFO

RLS is correctly documented as a frozen prior

DOCUMENTED
Status
The update mechanism works when explicitly invoked, but it is not wired into the operator. Current source comments no longer claim self-calibration.
Next step
If live calibration is added, wire a validated post-actuation measurement, include estimator state in determinism tests, and verify tenant-local ECost/CHi use the same calibrator instance.
F-07 · INFO

Telemetry NaN poisoning has source-level defenses

ADDRESSED
Status
Prometheus ingestion drops NaN/Inf values, and saturation functions neutralize NaN. This closes the previously reachable path from Prometheus "NaN" to optimizer cost.
Verification
Fix and contract tests are present in the source snapshot; fresh Go execution remains pending because this environment lacks the Go toolchain.
