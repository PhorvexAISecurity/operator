# NATS owned-subject observer command

This command is a **read-only protocol client**, intended for a separately admitted non-root fixture Pod. It uses the pinned harness dependency `github.com/nats-io/nats.go@v1.47.0`; local subprocess tests use the pinned `nats-server@v2.10.29`. It opens one credential-free NATS connection, disables reconnects, and never publishes, creates a stream, reads another subject, or invokes Phorvex.

The sole invocation shape is `nats-owned-observer --config <json-file>`. The coordinator must mount that config read-only; the command reads a regular file but does **not** enforce a read-only mount or file mode. Strict JSON is at most 1024 bytes and contains `brokerURL`, `subject`, `nonce`, `allowedServerIDs`, `expectedPayloadSHA256`, `connectTimeoutMillis`, `flushTimeoutMillis`, and `observeTimeoutMillis`. The coordinator must admit the exact fixed `nats://host:port` URL, generate a fresh random 96-bit lowercase-hex nonce, construct a concrete nonce-containing subject of at most 128 characters, and pin one to three distinct current Service endpoint server IDs before launching the process. The command refuses URL credentials, multi-URLs, wildcard subjects, unknown fields, excessive timeouts or duplicate server IDs. It accepts whichever one of the admitted server IDs the Service connection actually selects; it does not reconnect to seek a preferred broker. The pinned nats.go v1.47.0 library has no `IgnoreDiscoveredServers` option; `NoReconnect` and an exact-address custom dialer prevent adopting advertised endpoints for any dial.

After `SubscribeSync` and a bounded flush, stdout receives one JSON `subscription` receipt with the **actual** server ID. Only then may the coordinator map that ID to its exact broker Pod UID and release its separately controlled publication. The command then waits once and emits one JSON `observation` receipt. `EXACT_PAYLOAD_RECEIVED` requires the exact subject, `Nats-Msg-Id: cat-<nonce>`, at most 256 payload bytes, and the supplied SHA-256. Explicit server permission denial is `PERMISSION_DENIED`; no message before the deadline is `TIMEOUT_UNKNOWN`, never proof of denial. Wrong headers or hashes are `IDENTITY_MISMATCH`, and a 257-byte message is `OVERSIZE_INVALID`. No raw payload, token, URL or server error is printed. Connect, flush and observation deadlines sum to at most 45 seconds.

The command does not establish that its process ran in an isolated Pod, that a manager signal was produced, or that Phorvex prevented access. The coordinator must separately retain the exact client Pod UID/image/network and current broker Service/EndpointSlice mapping, join the subscription receipt to an independently verified event/decision, and keep the legitimate JetStream readback from the protocol adapter distinct. These integration steps are not implemented here; local subprocess tests are not an installed-cluster result.
