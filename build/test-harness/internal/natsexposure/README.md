# Owned NATS exposure protocol oracle

`Run` accepts two **already connected, distinct** `nats.Conn` actors: a fixture writer/intended JetStream consumer and a separately supplied client. The caller provides one nonce, exact stream/subject/consumer names containing it, expected server IDs, finite timeouts, and one synthetic payload of at most 256 bytes. Both connections must disable reconnects; the second must enable `PermissionErrOnSubscribe`. No credentials or connection URLs enter the receipt. Two connections in one process do **not** prove a remote Pod or location boundary; this library is only the protocol adapter.

The package refuses a preexisting stream, creates one file-backed stream with exact nonce/schema metadata (three-message, 1 MiB, 120-second, one-consumer bounds; 256-byte payload cap and 512-byte server wire cap including headers) and one owned durable consumer, then establishes and flushes the second client's core subscription **before** one publication. It records the real PubAck, legitimate fetch and ACK, independent stored-message readback, and the second client's exact payload hash, nonce message header, or explicit subscription permission error. A timeout is `UNKNOWN`, never a denial. It verifies broker IDs before and after the barrier and after observation, and deletes only the stream whose **create-response** timestamp, name, subject, limits, and owner metadata still match an independent read. Ambiguous create/publish/delete is not replayed; JetStream publish retries are explicitly zero. `Validity`, `Objective`, and `Cleanup` remain separate fields.

`Run` requires a `PhaseRecorder` and `BeforePublish` callback. The recorder must persist each supplied receipt and `fsync` its file and parent directory **before returning nil**; the library calls it before create, consumer creation, subscription, publication and deletion and after their key receipts. A recorder failure before a mutation aborts that mutation. Cleanup intent and final state use fresh bounded contexts after a canceled run context, so a context-aware recorder can still preserve them. The bounded `BeforePublish` callback runs once after the subscription is flushed and before publication; a runner may use it to join a separately produced event/manager decision. Its nil result only opens the barrier and is never interpreted here as a successful brain decision. The caller must honor the callback context deadline. Neither callback may include credentials in durable records.

The real NATS 2.10.29 in-process tests cover 256-byte exact delivery and 257-byte preflight refusal, subject denial, wrong broker/nonce refusal, no-message timeout, foreign-owner cleanup refusal, recorder/barrier failures including cancellation, and exactly one publish dispatch on a no-responder server. These are local protocol tests, **not** an installed-cluster result. The existing `jetstreamprobe` durability helper cannot be used directly here: it opens its own connection and exercises a different multi-message durability oracle, whereas this package must preserve the runner-supplied second client's identity and prepublication subscription.

The runner still needs to create and independently pin an uncredentialed, non-root in-cluster client Pod, map its connection's server ID to an exact serving broker Pod UID, validate current Service/EndpointSlice and NATS config, supply the two connections, and durably record intent before invoking `Run`. It must join any separate injected catalogue signal to the exact manager decision, and keep that signal/decision outcome apart from the protocol receipt. A no-auth broker accepting this synthetic message demonstrates the declared fixture confidentiality objective under that configuration; it does **not** establish an authorization bypass, natural detection, or mitigation. This package sends no Phorvex signal and performs no cluster or policy operation.
