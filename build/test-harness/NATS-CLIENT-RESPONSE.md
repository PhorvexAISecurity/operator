# Installed NATS owned-client response fixture

`nats-client-response` is a dedicated, unscored Scenario Catalog suite for `c2-nats-owned-client-response`. It uses a nonce-owned synthetic stream, an independent observer Pod in `phorvex-nats-exposure-fixture`, one injected SecurityEvent and a bounded installed-manager response window. The receipt must join the exact broker, source Pod, generated event, decision, actuator attempt, remote observer, legitimate consumer, and cleanup identities. A message received by an unauthenticated client is a configuration observation; silence, a missing receipt or an incomplete audit is **UNKNOWN**, never proof of enforcement. The case does not claim a subject-authorization bypass under the installed no-auth broker configuration.

The server-owned [config.nats-client-response.yaml](config.nats-client-response.yaml) is a template, not runnable with its `__SET_*__` placeholders. Before enabling the suite, review and replace its logical cluster target, current kube-system UID, installed NATS config hash, healthy fixture Node, console observer image digest, NATS broker image ID and manager image ID. `managerNamespace` and `managerDeployment` must identify the installed manager. The mounted NATS config hash binds the declared file; it does not alone attest process-loaded bytes. The console supplies each run's ID, fresh nonce and output path. Its named-suite route fixes the scenario and does not admit browser-supplied targets, images, subjects or arbitrary methods. Both `nats` and `phorvex-nats-exposure-fixture` tenant grants, plus the logical cluster and console-host grants, are required for authorized run access.

Installation requires the reviewed console image containing `/app/nats-owned-observer`, the existing NATS exposure baseline opt-in, and the additional chart value `phorvex.console.natsExposure.clientResponse.enabled=true`. Both values default to false. Enabling response while the console or baseline is disabled makes the chart fail. The response Role is confined to the dedicated fixture namespace: ConfigMaps get/create/delete; Pods get/create/list/patch/delete and Pod logs get; Deployments get/create/delete; ReplicaSets get/list/delete; PDBs get/create/delete; PhorvexPolicies get/list/create/delete; AMTDs and NetworkPolicies get/list/delete. The existing `nats` Role remains read/port-forward only. The console gains no namespace create/delete, Secret, ServiceAccount or RBAC write grant from this opt-in. Existing cluster SecurityEvent authority is the event path. Admission must confirm the installed source, grants and both tenant bindings before execution.

One run may create only exact nonce-owned resources in the fixed fixture namespace. The coordinator records intent and returned UIDs before each mutation, refuses ambiguous writes without replay, and cleans up by exact UID. The namespace and shared broker are preserved. Partial journal, unknown mutation, uncertain cleanup, identity drift, missing independent observer evidence or audit gaps remain inconclusive and unsafe to retry until read-only reconciliation proves the original owned resources absent. Even a complete response receipt is a measured mechanism and effect chain, not a natural-detection or general defense-efficacy score. No live result is claimed by this configuration document.
