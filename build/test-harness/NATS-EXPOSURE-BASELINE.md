# Installed NATS synthetic exposure baseline

This is one no-signal configuration measurement of the installed `nats` broker. It publishes one nonce-owned JetStream message, waits for the intended consumer's ACK and stored hash, and observes whether a separate credential-free Pod receives that exact synthetic payload. `EXPOSED` means the remote Pod received the owned message under the observed configuration. It is not a permission bypass, customer-data disclosure, detector result, brain decision, actuator effect, or defense-efficacy verdict.

The ordinary console entry is the **NATS exposure control** in Scenario Catalog. It calls `POST /api/runs/start` with `{"config":"nats-exposure-baseline","nativeActuator":false}`; the generic multi-arm `/api/runs/scenario` route explicitly refuses this case. Read `GET /api/runs/status?id=<returned-id>` and `GET /api/runs/evidence?id=<returned-id>`. The console UI shows the configuration finding separately from security scores. A complete result requires the same run ID and namespace UID in the protocol artifact, benign metric, final provenance and terminal fixture-resource receipt. A remote payload observation remains visible but unaccepted if cleanup or a later identity check is inconclusive.

The server-owned `maxRunSeconds` caps the NATS run context, and its in-cluster Kubernetes REST transport has a 20-second per-request timeout. Owned cleanup uses separate bounded contexts. A proven pre-effect refusal or incomplete measurement with verified exact cleanup remains unaccepted but permits a fresh run. Stop, restart, ambiguous mutation or unverified cleanup leaves the run partial and unsafe to retry. An authorized operator can call `POST /api/runs/nats-reconcile?id=<run-id>` with `{"id":"<run-id>"}` after the original run has stopped; the same logical target and both tenant grants are checked again. This performs one bounded **read-only** exact-identity check of the original process fence, broker route, nonce stream absence and owned Pod/ConfigMap absence. It never replays or deletes the fixture. A missing pre-effect anchor, legacy unfenced run, changed namespace/cluster/route, present stream or uncertain read leaves the run unsafe. A successful reconciliation permits a new run while retaining the original result as partial.

Installation is an explicit opt-in:

1. Build and install the reviewed console image from `deploy/docker/console.Dockerfile`. It contains both `/data/build/test-harness/bin/harness.exe` and `/app/nats-owned-observer`; the fixture Pod uses the **installed console image digest**, with no runtime source download or copied user credential. Keep the console's authenticated run state persistent.
2. Enable `phorvex.console.natsExposure.enabled=true` in the `phorvex` chart with the console enabled. This creates only `phorvex-nats-exposure-fixture` and grants the console ServiceAccount Pod/ConfigMap get/create/delete there, Pod logs there, and read/Pod port-forward access in `nats`. It grants no namespace create/delete, Secret or RBAC writes. The dedicated namespace is retained across runs; each run deletes only its own UID-bound observer Pod and ConfigMap. The installed broker Service/StatefulSet/ConfigMap and Node are read only.
3. Replace each `__SET_*__` placeholder in the server-owned `config.nats-exposure-baseline.yaml` with the reviewed **logical cluster target** used by console grants, current kube-system UID, declared `nats.conf` SHA-256, healthy observer Node name, installed console image digest, and broker image ID digest. The transport marker is `natsExposureFixture.transport: in-cluster`; it is not the authorization target. The namespace is fixed to `phorvex-nats-exposure-fixture`, and the broker tenant is `nats`. The console allocates a fresh 96-bit nonce and captures transient namespace, Pod, EndpointSlice, container and server identities at launch; operators do not copy historical per-run UIDs into the suite. A stale or mismatched pin refuses before publication. The ConfigMap SHA binds the declared source; it does not by itself attest loaded process bytes. Process `/varz` and independent protocol receipt supply separate observations.
4. Give the authenticated operator grant the console-host target, that exact logical cluster target, and **both** tenants `nats` and `phorvex-nats-exposure-fixture`. Both tenant grants are required at launch and again for run-ID/list/stop visibility. The browser cannot supply a different suite, namespace, context, broker or image for this case.

The `nats` server currently has no broker authentication in this admitted configuration. This control characterizes that configuration with an owned payload; it does not claim that a deployed subject ACL was bypassed. It emits no SecurityEvent and does not infer a target-specific no-action reason from manager status counters. A separate signaled security case requires its own exact event, decision, actuator and independent outcome chain.
