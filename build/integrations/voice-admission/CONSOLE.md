The admission Live case uses `/api/voice/admission/live/fire` with the fixed
`voice-unauthenticated-media-admission` scenario. It is disabled by default.
Install the reviewed runtime wrapper, SDK image, initial admission policy and
protected empty journal before enabling native admission and its Console
profile. Runtime activation remains owned by `render_activation.py`; this
Console renderer outputs only the new immutable profile and chart pins.

`render_profile.py` consumes the returned wrapper and admission policy
ConfigMaps. It checks their exact UIDs/ownership, canonical seven-field URL
profile, reviewed repository source bytes, unchanged four-file legacy bundle,
initial observe rule, fixed probe/audio and audit identity. It performs no
cluster calls or credential reads. Its `console-values.json` is a subchart
values file; `umbrella-values.json` has the additional umbrella nesting. Package
the final subchart into the umbrella release before installation. Preserve
existing values when adding these fragments. Do not apply any old policy
activation renderer or recreate an existing policy/journal.

A Fire creates a bounded client inside one exact pinned serving bot. It first
runs one signed ordinary audio control, then one unsigned ordinary audio turn
and one unsigned pending connection. The client lifetime is capped at 420
seconds. Its signing token and headers stay in memory. The receipt producer
observes actual STT, model text/completion and TTS frames separately from actual
outbound WebSocket audio. Console requires the runtime's immutable unsigned
exposure pair before emitting a labeled TEST_INJECTED SecurityEvent. Missing,
stale, mismatched or incomplete evidence stays UNKNOWN; any observed first
loss stays visible in `firstLanded` and the historical attack outcome.

Only a matching normal brain decision, exact protected terminal journal,
authenticated settled receipts for every current serving Pod, completed pending
and active unsigned delegates, fresh unsigned/malformed rejection on every Pod
and unsigned Service rejection can reach the control phase. The original
signed session must continue with another measured STT/model/TTS audio turn;
a new signed session must also produce measured audio. API drift, loss of a
serving Pod, control failure or unconfirmed run-owned cleanup removes defense
credit. The final rule is checked again before publishing the result.

Cleanup closes only the run-owned client sockets and waits for delegated
completion. It deletes only the exact synthetic calls' transcripts/context and
admission receipt files; it never resets enforcement. Later Fire on enforced
revision one reports ALREADY_PROTECTED and emits no new event or first-loss
trial. Existing Memory, Refund, MCP and Output probes use the official Twilio
SDK signature for the pinned production URL and retain their existing inner
protocols, clips, audio counters and evidence. Their first fixture/baseline
operation verifies SDK/signing availability before a new fixture write.

This case measures bounded unsigned media admission and local pipeline/session
teardown through the application and Service routes. The telephone network,
actual caller/account ownership, public Internet reachability, stolen-signature
replay and remote inference cancellation are not established by these probes.
The separate installed-Pipecat teardown proof is required for native terminal
success. No financial savings are inferred from local frame counts.
